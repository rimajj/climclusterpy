Install climclusterpy
=====================

``climclusterpy`` requires Python 3.11 or later. The repository builds two distributions with
the same code and the same ``import climclusterpy``:

``climclusterpy``
   The full package. It installs ``climclusterpy-base`` together with PyTorch (learned
   distances), GeoPandas (ecoregion maps) and Cartopy (map plots).
``climclusterpy-base``
   The same code without PyTorch, GeoPandas and Cartopy. It covers Euclidean clustering,
   Köppen–Geiger supervision and reconstruction. A feature that needs a missing dependency
   raises an ``ImportError`` that names what to install.

.. code-block:: console

   $ pip install climclusterpy          # full package
   $ pip install climclusterpy-base     # without PyTorch, GeoPandas and Cartopy

.. important::

   Neither distribution is on PyPI yet. Until then, install from the GitLab repository, or
   build both distributions from a checkout. The repository's own distribution is
   ``climclusterpy-base``, and the ``[all]`` extra adds what the full package adds.

To install from the repository, run the command below. pip clones the repository, so
``gitlab.pik-potsdam.de`` must be reachable, and you need read access if the project is not
public to you:

.. code-block:: console

   $ pip install "climclusterpy-base[all] @ git+https://gitlab.pik-potsdam.de/lpjmlfit_analysis/climclusterpy.git"

To read or change the code, install from a checkout instead:

.. code-block:: console

   $ git clone https://gitlab.pik-potsdam.de/lpjmlfit_analysis/climclusterpy.git
   $ cd climclusterpy
   $ pip install -e '.[all]'

``scripts/build_dists.sh`` builds both distributions into ``dist/``. To install the full
package from there, run ``pip install --find-links dist climclusterpy``.

Check the installation:

.. code-block:: console

   $ python -c "import climclusterpy; print(climclusterpy.__version__)"
   $ climclu --help

Both commands work without any optional dependency, because ``import climclusterpy`` loads
PyTorch, GeoPandas and Cartopy only when you call a feature that needs them.

Extras
------

Extras add optional dependencies to either distribution, for example ``climclusterpy[spei]``
or ``climclusterpy-base[lmnn]``.

.. list-table::
   :header-rows: 1
   :widths: 16 34 50

   * - Extra
     - Adds
     - Enables
   * - ``[lmnn]``
     - ``torch``
     - Learned distances (``locally_weighted=True``), every mode. Part of ``climclusterpy``.
   * - ``[ecoregions]``
     - ``geopandas``
     - Ecoregion supervision, and regions from a shapefile. Part of ``climclusterpy``.
   * - ``[viz]``
     - ``cartopy``
     - Map plots. Part of ``climclusterpy``.
   * - ``[spei]``
     - ``pyet``
     - The SPEI and potential-evapotranspiration features
       (``climate_variables=[..., "spei"]``). ``[features]`` is the former name and still
       works.
   * - ``[mpi]``
     - ``mpi4py``
     - Clustering and grid writing across MPI ranks.
   * - ``[all]``
     - ``[lmnn]``, ``[ecoregions]``, ``[viz]``, ``[spei]``
     - Every optional capability except MPI.
   * - ``[test]``, ``[docs]``, ``[dev]``
     - test, documentation and development tools
     - Repository checkouts only (``climclusterpy-base``).

By default, the package does not compute the SPEI features.
:func:`~climclusterpy.create_clusters` summarizes ``tas``, ``pr``, ``rsds``, ``rlds`` and
``hurs`` unless ``"spei"`` is added to ``climate_variables``. Without ``pyet`` that request
fails with a message naming the package.

GeoPandas and Cartopy with conda
--------------------------------

GeoPandas and Cartopy depend on the native GEOS, PROJ and GDAL libraries, which pip
sometimes cannot build. In that case, install them from conda-forge first and then the package:

.. code-block:: console

   $ conda install -c conda-forge cartopy geopandas
   $ pip install -e '.[lmnn,spei]'

PyTorch on CPU or GPU
---------------------

To select a CPU-only or a specific CUDA build of PyTorch, install ``torch`` from the PyTorch
index first and then the package:

.. code-block:: console

   $ pip install torch --index-url https://download.pytorch.org/whl/cpu
   $ pip install -e '.[lmnn]'

Learned distances run on CPU.

Environment variables
---------------------

You do not need to set any of these variables. They tune how much data the package reads or
holds in memory at a time, and everything that changes what is computed is a function
argument instead. A value that cannot be read (a word where a number is expected, a
negative size) stops the run with an error that names the variable.

.. list-table::
   :header-rows: 1
   :widths: 38 12 50

   * - Variable
     - Default
     - What it sets
   * - ``CLIMCLUSTERPY_CHUNK_TIME``
     - 500
     - Time steps per chunk when an input NetCDF is opened. A smaller value uses less memory per
       step of work. Averages over time are summed chunk by chunk, so another chunk length
       can move them in the last floating-point digit, never more.
   * - ``CLIMCLUSTERPY_DISTRIBUTED_TIME_CHUNK``
     - 2000
     - Time steps read at once when the cells of a ``cell_selection="distributed"`` grid
       are extracted.
   * - ``CLIMCLUSTERPY_DISTRIBUTED_EXPAND_THRESHOLD_GB``
     - 50
     - Size (GB) of one extracted variable above which a cell drawn into several patches
       is held in memory once and copied out only when the files are written.
   * - ``CLIMCLUSTERPY_DIRECT_READ``
     - 1
     - ``0`` turns off reading distributed cells straight from the input files and reads
       them through xarray instead. Both give identical results, and the direct read is faster.
   * - ``CLIMCLUSTERPY_DEBUG``
     - 0
     - ``1`` makes the ``climclu`` command print the full Python traceback instead of a
       one-line error. Any value other than empty, ``0``, ``false``, ``no`` or ``off``
       turns it on.

Yes/no variables accept ``1``/``0``, ``true``/``false``, ``yes``/``no`` and ``on``/``off``.

One variable, ``LPJROOT``, belongs to LPJmL rather than to climclusterpy. When it is set,
:func:`~climclusterpy.convert_netcdf_to_clm` looks for the ``cdf2clm`` and ``cdf2soil``
tools in ``$LPJROOT/bin`` before the ``PATH``. You can also pass ``tools_dir=``.

.. versionchanged:: 0.4.0
   The variables gained the ``CLIMCLUSTERPY_`` prefix (they were ``CHUNK_TIME``,
   ``DISTRIBUTED_TIME_CHUNK``, ``DISTRIBUTED_EXPAND_THRESHOLD_GB`` and ``CCP_DIRECT_READ``);
   the package ignores an old name that is still set and prints a warning. ``MAX_TIME_STEPS``, which
   silently shortened the climate series used for clustering, no longer exists. To cluster
   on a shorter period, select it from the input before you pass it in.

Build this documentation
------------------------

To build the documentation, run:

.. code-block:: console

   $ pip install -e '.[docs]'
   $ sphinx-build -W docs/src docs/_build/html
