Methods
=======

The algorithms and data transformations implemented in ``climclusterpy``, in the order in
which a run applies them, followed by the reduced grid and the check that a reconstruction is
correct.

Data Acquisition and Preprocessing
-----------------------------------

Climate and Static-Field Loading
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

NetCDF input is read by :mod:`climclusterpy.data.loader` (the fixed LPJmL-FIT file layout)
and :mod:`climclusterpy.data.generic_input` (any named climate and static fields). Both
share the characteristics below, and both align every field to one grid that the land mask
or cell list defines.

**Chunked Processing**

Climate datasets are loaded using Dask with configurable chunk sizes (default 500 time steps):

.. code-block:: python

   ds = xr.open_dataset(path, chunks={"time": 500})

This enables:

* Parallel computation across chunks
* Memory-efficient processing of large datasets (>10 GB)
* Lazy evaluation of array operations

**Memory Optimization**

All float64 data variables are automatically converted to float32:

.. math::

   \text{Memory}_{\text{optimized}} = 0.5 \times \text{Memory}_{\text{original}}

This transformation preserves sufficient numerical precision (7 significant digits) for climate data while halving memory consumption.

**Coordinate Standardization**

Latitude and longitude coordinates are:

1. Canonicalized to standard names (``latitude``, ``longitude``)
2. Rounded to 5 decimal places (:math:`10^{-5}` degrees ≈ 1.1 m spatial resolution)
3. Validated for grid compatibility across datasets

Variable names are resolved through these synonyms (a file with a single data variable is
used whatever the variable is called):

.. code-block:: text

   precipitation: tpr, pr, precip, precipitation_flux, tp
   temperature: TMean, tmean, tas, t2m, temp
   radiation: SWR, rsds, SWdown, swdown, LWR, rlds, LWdown
   humidity: hurs, humid, rh, relative_humidity

**Grid Compatibility Validation**

The ``climclusterpy.data.coords.check_grid_compatibility()`` function ensures spatial alignment:

.. math::

   \forall i,j: |\text{lat}^A_i - \text{lat}^B_i| < \epsilon \land |\text{lon}^A_j - \text{lon}^B_j| < \epsilon

where :math:`\epsilon = 10^{-5}` degrees, i.e. the coordinates must be identical after rounding
to 5 decimals. A climate input that is not on the grid of the land mask (or cell list, or
first field) is an error, not regridded: regrid it before loading. Static fields may sit on a
slightly different grid and are then mapped onto the reference grid by nearest neighbour,
with a warning.

Data Registry
~~~~~~~~~~~~~

The :class:`climclusterpy.data.DataRegistry` manages spatial grids and valid cell identification.

**Valid Cell Identification**

A boolean mask :math:`\mathbf{M} \in \{0,1\}^{n_{\text{lat}} \times n_{\text{lon}}}` identifies valid cells.
It is built from whatever defines the model's cells: a land-mask file (non-zero and not
missing), a list of cell coordinates, or, with neither, every cell where all fields have data.
For the LPJmL-FIT file layout the mask is the soil code:

.. math::

   M_{ij} = \begin{cases}
   1 & \text{if soil\_code}_{ij} \neq \text{sentinel} \land \neg \text{isnan}(\text{soil\_code}_{ij}) \\
   0 & \text{otherwise}
   \end{cases}

Missing values in a mask file or soil code are detected hierarchically:

1. NetCDF encoding attributes (``_FillValue``, ``missing_value``)
2. Common integer sentinels, when neither attribute is set: :math:`-9999, -999, 9999, -32768, -10^6`
3. NaN values in floating-point arrays

**Flattening Operation**

The :meth:`climclusterpy.data.DataRegistry.flatten_on_valid` method projects multi-dimensional arrays onto the 1D valid cell space:

.. math::

   \mathbf{X}_{\text{flat}} = \text{extract}(\mathbf{X}_{\text{grid}}, \mathbf{M}) \in \mathbb{R}^{n_{\text{valid}} \times n_{\text{time}}}

where :math:`n_{\text{valid}} = \sum_{i,j} M_{ij}`.

This operation:

* Reduces memory by eliminating invalid cells (ocean, missing data)
* Accelerates computation by operating on contiguous arrays
* Maintains spatial correspondence through the registry's ID mapping

Ecoregion Assignment
--------------------

The :mod:`climclusterpy.supervision.ecoregions` module assigns grid cells to ecological regions through spatial intersection.

**Spatial Join Algorithm**

Given:

* Ecoregion polygons :math:`\{P_1, P_2, \ldots, P_K\}` with identifiers :math:`\{e_1, e_2, \ldots, e_K\}`
* Grid cell points :math:`\{\mathbf{p}_1, \mathbf{p}_2, \ldots, \mathbf{p}_n\}` where :math:`\mathbf{p}_i = (\text{lat}_i, \text{lon}_i)`

The assignment function is:

.. math::

   \text{ecoregion}(\mathbf{p}_i) = \begin{cases}
   e_k & \text{if } \mathbf{p}_i \cap P_k \neq \emptyset \\
   \text{null} & \text{otherwise}
   \end{cases}

**Coordinate Normalization**

Longitude coordinates are normalized to :math:`[-180, 180)`:

.. math::

   \text{lon}_{\text{norm}} = ((\text{lon} + 180) \mod 360) - 180

This ensures consistency with standard ecoregion shapefiles (e.g., Ecoregions2017 from Dinerstein et al., 2017).

**Implementation**

The :func:`climclusterpy.supervision.assign_cells_to_ecoregions` function uses GeoPandas vectorized spatial join:

.. code-block:: python

   matched = gpd.sjoin(
       points_gdf,
       ecoregions_gdf,
       how='left',
       predicate='intersects'
   )

The ``intersects`` predicate (rather than ``within``) includes cells lying precisely on polygon boundaries, maximizing spatial coverage.

Ecological Feature Summarization
---------------------------------

Time series climate data are transformed into interpretable ecological summary statistics by the :mod:`climclusterpy.features` module. The columns that :func:`~climclusterpy.create_clusters` builds, and how to choose them, are listed in :doc:`../howto/features`. The ecology diagnostics and the block PCA below are building blocks that ``create_clusters`` does not apply.

Temperature Features
~~~~~~~~~~~~~~~~~~~~

For temperature time series :math:`\{T_1, T_2, \ldots, T_{n_t}\}`, the following statistics are computed by ``climclusterpy.features.climate._summarize_temperature()``:

**Annual Mean**

.. math::

   \mu_T = \frac{1}{n_t} \sum_{t=1}^{n_t} T_t

**Annual Standard Deviation**

.. math::

   \sigma_T = \sqrt{\frac{1}{n_t} \sum_{t=1}^{n_t} (T_t - \mu_T)^2}

**Annual Range**

.. math::

   R_T = \max_t(T_t) - \min_t(T_t)

**Seasonality**

Monthly climatology is computed by averaging each calendar month across all years:

.. math::

   \bar{T}_m = \frac{1}{n_y} \sum_{y=1}^{n_y} T_{y,m} \quad \text{for } m \in \{1, 2, \ldots, 12\}

Seasonality is then defined as the standard deviation of monthly means:

.. math::

   S_T = \sqrt{\frac{1}{12} \sum_{m=1}^{12} (\bar{T}_m - \mu_T)^2}

This captures the amplitude of seasonal temperature variation.

Precipitation Features
~~~~~~~~~~~~~~~~~~~~~~

For precipitation time series :math:`\{P_1, P_2, \ldots, P_{n_t}\}`, ``climclusterpy.features.climate._summarize_precipitation()`` computes:

**Annual Mean**

.. math::

   \mu_P = \frac{1}{n_t} \sum_{t=1}^{n_t} P_t

**Coefficient of Variation**

.. math::

   \text{CV}_P = \frac{\sigma_P}{\mu_P}

where :math:`\sigma_P` is the temporal standard deviation. CV quantifies relative precipitation variability.

**Wet-Day Frequency**

.. math::

   f_{\text{wet}} = \frac{1}{n_t} \sum_{t=1}^{n_t} \mathbb{1}(P_t > \theta)

where :math:`\theta = 1` mm is the wet-day threshold and :math:`\mathbb{1}(\cdot)` is the indicator function.

**Maximum Monthly Precipitation**

.. math::

   P_{\max} = \max_{t \in \{1, \ldots, n_t\}} P_t

This captures extreme precipitation events.

Radiation Features
~~~~~~~~~~~~~~~~~~

For shortwave (:math:`R_s`) and longwave (:math:`R_l`) radiation, ``climclusterpy.features.climate._summarize_radiation()`` computes:

.. math::

   \begin{align}
   \mu_R &= \frac{1}{n_t} \sum_{t=1}^{n_t} R_t \quad \text{(annual mean)} \\
   \sigma_R &= \sqrt{\frac{1}{n_t} \sum_{t=1}^{n_t} (R_t - \mu_R)^2} \quad \text{(annual std)} \\
   A_R &= \max_t(R_t) - \min_t(R_t) \quad \text{(seasonal amplitude)}
   \end{align}

Humidity Features
~~~~~~~~~~~~~~~~~

For relative humidity :math:`\{H_1, H_2, \ldots, H_{n_t}\}`, ``climclusterpy.features.climate._summarize_humidity()`` computes:

.. math::

   \begin{align}
   \mu_H &= \frac{1}{n_t} \sum_{t=1}^{n_t} H_t \quad \text{(annual mean)} \\
   \sigma_H &= \sqrt{\frac{1}{n_t} \sum_{t=1}^{n_t} (H_t - \mu_H)^2} \quad \text{(annual std)} \\
   H_{\min} &= \min_t(H_t) \quad \text{(dry-season minimum)}
   \end{align}

Static-Field Features
~~~~~~~~~~~~~~~~~~~~~

Every static field (soil, elevation, land cover, …) is declared ``"continuous"`` (kept as one
numeric feature) or ``"categorical"`` (an integer class code, one-hot encoded so all classes
are equally far apart). For the LPJmL-FIT layout,
:func:`climclusterpy.features.summarize_soil_features` extracts the soil depth as a continuous
feature and the soil code as a categorical one.

For a static field with a time dimension, the first time step is used, under the assumption of temporal invariance.

Köppen–Geiger Diagnostic Scalar Features
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Eight continuous KG-diagnostic scalar features are computed directly from the monthly climatologies and latitude by :func:`climclusterpy.features.compute_kg_diagnostic_features`, capturing the core rule quantities used by Köppen–Geiger classification:

* **kg_diag_T_cold**, **kg_diag_T_warm**: Coldest and warmest month temperature
* **kg_diag_P_dry_min**, **kg_diag_P_wet_max**: Driest and wettest month precipitation
* **kg_diag_P_dry_summer**, **kg_diag_P_dry_winter**: Hemisphere-aware dry-season precipitation minima
* **kg_diag_P_seasonality_ratio**: Wettest-to-driest precipitation ratio, clipped to :math:`[1, 100]`
* **kg_diag_aridity_index**: Aridity index offset from the KG threshold :math:`P_{\text{ann}} - (2 T_{\text{ann}} + 28)`

These ``kg_diag_`` features are protected from removal in the filtering stages.

Ecology Diagnostic Features
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Thirteen ecophysiological features are computed from the monthly climatologies by :func:`climclusterpy.features.compute_all_ecology_diagnostic_features`, capturing water-balance characteristics and thermal thresholds relevant to vegetation dynamics. These ``eco_diag_`` features are protected from removal during correlation and PCA filtering stages.

**Vapour Pressure Deficit (VPD)**

Monthly VPD is computed from monthly temperature :math:`\bar{T}_m` and relative humidity :math:`\bar{H}_m`:

.. math::

   \mathrm{VPD}_m = e_s(\bar{T}_m)\,(1 - \bar{H}_m / 100), \qquad e_s(T) = 0.6108 \exp\!\left(\frac{17.27\,T}{T + 237.3}\right)\ \text{[kPa]}

Three features are derived:

* **eco_diag_vpd_mean**: Annual mean :math:`\overline{\mathrm{VPD}} = \tfrac{1}{12}\sum_m \mathrm{VPD}_m`
* **eco_diag_vpd_max_monthly**: Maximum monthly value :math:`\max_m \mathrm{VPD}_m`
* **eco_diag_vpd_stress_months**: Count of months with :math:`\mathrm{VPD}_m > 1.5` kPa

**Growing Degree Days (GDD)**

Thermal accumulation indices computed from monthly temperature:

.. math::

   \mathrm{GDD}_b = \sum_{m=1}^{12} \max(0,\;\bar{T}_m - b)\,\cdot\, n_{\mathrm{days},m}

* **eco_diag_gdd_5**: Base :math:`b = 5\,°\text{C}` (cool-season crops, boreal vegetation)
* **eco_diag_gdd_10**: Base :math:`b = 10\,°\text{C}` (warm-season crops, temperate vegetation)

**Frost-Free Days**

.. math::

   F = \sum_{m=1}^{12} \mathbb{1}(\bar{T}_m > 0)\,\cdot\, n_{\mathrm{days},m}

* **eco_diag_frost_free_days**: Distinguishes transitional climates where frost occurrence is intermittent.

**Potential Evapotranspiration and Moisture Balance**

Monthly PET is estimated via the Priestley–Taylor method (where radiation data are available) or Thornthwaite approximation:

* **eco_diag_pet_mean**: Annual mean PET (mm day\ :sup:`-1`)
* **eco_diag_p_pet_ratio**: Annual precipitation-to-PET ratio :math:`\overline{P}/\overline{\mathrm{PET}}` (moisture index)
* **eco_diag_water_deficit_months**: Count of months where :math:`\bar{P}_m < \mathrm{PET}_m`

**Dry Spells**

Consecutive runs of months with :math:`\bar{P}_m < 30` mm are identified:

* **eco_diag_dry_spell_max**: Maximum spell length across the annual cycle
* **eco_diag_dry_spell_mean**: Mean spell length

These capture the persistence of dry seasons beyond their total duration.

**Precipitation Intensity and Seasonality**

* **eco_diag_precip_intensity_wet_days**: Mean precipitation per wet month :math:`\bar{P}_{\mathrm{wet}} = \sum_m \bar{P}_m \mathbb{1}(\bar{P}_m > 30) / \sum_m \mathbb{1}(\bar{P}_m > 30)`
* **eco_diag_precip_wettest_quarter_frac**: Fraction of annual precipitation falling in the wettest quarter :math:`f_{\mathrm{wq}} = P_{\mathrm{wq}} / P_{\mathrm{ann}}`

Feature Combination
~~~~~~~~~~~~~~~~~~~

:func:`climclusterpy.features.combine_features` merges climate and soil DataFrames through an inner join on ``cell_id``, ``latitude``, and ``longitude``, producing the raw feature matrix:

.. math::

   \mathbf{X}_{\text{raw}} \in \mathbb{R}^{n \times p}

where :math:`n` is the number of cells and :math:`p` is the total feature count (typically :math:`p \approx 20`–50 before filtering).

Feature Standardization and Filtering
--------------------------------------

Z-Score Standardization
~~~~~~~~~~~~~~~~~~~~~~~

:func:`climclusterpy.features.standardize_features` applies z-score transformation:

.. math::

   \mathbf{X}_{ij}^{\text{std}} = \frac{\mathbf{X}_{ij}^{\text{raw}} - \mu_j}{\sigma_j}

where:

.. math::

   \begin{align}
   \mu_j &= \frac{1}{n} \sum_{i=1}^n \mathbf{X}_{ij}^{\text{raw}} \\
   \sigma_j &= \sqrt{\frac{1}{n} \sum_{i=1}^n (\mathbf{X}_{ij}^{\text{raw}} - \mu_j)^2}
   \end{align}

This ensures:

* Zero mean: :math:`\mathbb{E}[\mathbf{X}_{:j}^{\text{std}}] = 0`
* Unit variance: :math:`\text{Var}(\mathbf{X}_{:j}^{\text{std}}) = 1`
* Comparability across features with disparate units

Correlation-Based Feature Removal
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

:func:`climclusterpy.features.remove_correlated_features` eliminates highly correlated features to mitigate multicollinearity.

**Correlation Computation**

Spearman rank correlation coefficients are computed for all feature pairs:

.. math::

   \rho_{jk} = \text{corr}_{\text{Spearman}}(\mathbf{X}_{:j}^{\text{std}}, \mathbf{X}_{:k}^{\text{std}})

Spearman correlation is preferred over Pearson as it captures monotonic (not just linear) relationships and is robust to outliers.

**Iterative Removal**

For each pair :math:`(j, k)` satisfying :math:`|\rho_{jk}| > \theta_{\text{corr}}` (default :math:`\theta_{\text{corr}} = 0.9`):

1. Compute mean absolute correlation for each feature:

   .. math::

      \bar{\rho}_j = \frac{1}{p-1} \sum_{k \neq j} |\rho_{jk}|

2. Remove the feature with higher :math:`\bar{\rho}`:

   .. math::

      \text{remove}(j) \text{ if } \bar{\rho}_j > \bar{\rho}_k

This greedy strategy preserves features with lower overall correlation.

Soil features are excluded from correlation analysis as they represent static, discrete properties.

Block PCA Compression of Monthly Profiles
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

:func:`climclusterpy.features.apply_block_pca_compression` reduces redundancy in the 12-dimensional monthly climatology profiles while preserving seasonal structure.

A separate PCA is fit to the temperature-monthly block (``tas_month_01..12``) and the precipitation-monthly block (``pr_month_01..12``). For each block, the minimum number of components explaining at least 99% of within-block variance is retained. Raw monthly columns are dropped and replaced by **whitened** PC scores:

.. math::

   \tilde{z}_{ik} = \frac{z_{ik}}{\sqrt{\lambda_k^{\text{block}}}}

where :math:`z_{ik}` is the raw PCA score of cell :math:`i` on block-PC :math:`k` and :math:`\lambda_k^{\text{block}}` is the corresponding eigenvalue (explained variance). Whitening ensures that all PC scores have unit variance, consistent with the z-scored summary features, and prevents high-variance leading PCs from dominating the downstream LMNN metric.

The resulting features are named ``tas_month_PC1..N_T`` and ``pr_month_PC1..N_P``. Fitted PCA objects are cached to disk (``block_pca_tas.pkl``, ``block_pca_pr.pkl``) to ensure consistent reuse across runs.

PCA-Based Diagnostic Filtering
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

:func:`climclusterpy.features.diagnostic_pca_filter` uses PCA to identify low-contribution features without dimensionality reduction.

**Algorithm**

1. Compute full PCA decomposition of :math:`\mathbf{X}^{\text{decorr}}`:

   .. math::

      \mathbf{X}^{\text{decorr}} = \sum_{i=1}^p \lambda_i \mathbf{u}_i \mathbf{v}_i^\top

   where :math:`\lambda_i` are eigenvalues (explained variances) and :math:`\mathbf{v}_i` are principal component loadings.

2. Determine minimum :math:`m` satisfying variance threshold :math:`\theta_{\text{var}} = 0.95`:

   .. math::

      m = \min \left\{ k : \sum_{i=1}^k \lambda_i \geq \theta_{\text{var}} \sum_{i=1}^p \lambda_i \right\}

3. For each original feature :math:`j`, compute total absolute contribution across the first :math:`m` components:

   .. math::

      C_j = \frac{1}{m} \sum_{i=1}^m |v_{ij}|

4. Normalize contributions:

   .. math::

      C_j^{\text{norm}} = \frac{C_j}{\sum_{k=1}^p C_k}

5. Remove features with :math:`C_j^{\text{norm}} < \theta_{\text{contrib}}` (default :math:`\theta_{\text{contrib}} = 0.01`).

This retains features substantially contributing to the dominant variance modes while eliminating redundant or low-information variables.

**Output**

The final feature set :math:`\mathbf{X} \in \mathbb{R}^{n \times d}` (where :math:`d \ll p`) combines:

* Filtered climate features (correlation + PCA filtered)
* Unfiltered soil features (preserved as static environmental descriptors)

Large Margin Nearest Neighbor (LMNN) Metric Learning
-----------------------------------------------------

The :mod:`climclusterpy.clustering` module learns a distance from a supervision signal in one of three modes (``lmnn_mode``): ``"global"``, and the per-cell ``"lowrank"`` and ``"diagonal"`` forms.

Global LMNN
~~~~~~~~~~~

:mod:`climclusterpy.clustering.lmnn` implements classic LMNN (Weinberger & Saul, 2009) with a single global Mahalanobis distance.

**Mahalanobis Distance**

The learned metric is defined by transformation matrix :math:`\mathbf{L} \in \mathbb{R}^{d' \times d}`:

.. math::

   D_M(\mathbf{x}_i, \mathbf{x}_j) = \sqrt{(\mathbf{x}_i - \mathbf{x}_j)^\top \mathbf{M} (\mathbf{x}_i - \mathbf{x}_j)}

where:

.. math::

   \mathbf{M} = \mathbf{L}^\top \mathbf{L} \in \mathbb{R}^{d \times d}

is the learned Mahalanobis matrix.

**Optimization Objective**

LMNN minimizes:

.. math::

   \mathcal{L}_{\text{LMNN}} = (1-\mu) \mathcal{L}_{\text{pull}} + \mu \mathcal{L}_{\text{margin}}

where:

.. math::

   \begin{align}
   \mathcal{L}_{\text{pull}} &= \sum_{i=1}^n \sum_{j \in \mathcal{T}_i} D_M^2(\mathbf{x}_i, \mathbf{x}_j) \\
   \mathcal{L}_{\text{margin}} &= \sum_{i=1}^n \sum_{j \in \mathcal{T}_i} \sum_{l \notin \mathcal{T}_i} \xi_{ijl}
   \end{align}

subject to:

.. math::

   D_M^2(\mathbf{x}_i, \mathbf{x}_l) - D_M^2(\mathbf{x}_i, \mathbf{x}_j) \geq 1 - \xi_{ijl}, \quad \xi_{ijl} \geq 0

Here:

* :math:`\mathcal{T}_i` = set of :math:`k` nearest same-ecoregion neighbors (target neighbors)
* :math:`l` indexes different-ecoregion cells (impostors)
* :math:`\mu \in [0,1]` balances pull vs. margin terms
* :math:`\xi_{ijl}` are slack variables for soft constraints

**Interpretation**

* **Pull term**: Minimizes distances to same-ecoregion neighbors
* **Margin term**: Enforces separation from different-ecoregion cells with margin = 1

**Feature Importance**

Feature importance is extracted from the diagonal of :math:`\mathbf{M}`:

.. math::

   I_j = M_{jj}

with normalization:

.. math::

   I_j^{\text{norm}} = \frac{I_j}{\sum_{k=1}^d I_k}

Large values indicate features strongly influencing the learned metric.

**Feature Transformation**

:func:`climclusterpy.clustering.lmnn.transform_features` projects data into the learned metric space:

.. math::

   \mathbf{X}^{\text{LMNN}} = \mathbf{X} \mathbf{L}^\top

In this space, Euclidean distance equals the original Mahalanobis distance:

.. math::

   \|\mathbf{x}_i^{\text{LMNN}} - \mathbf{x}_j^{\text{LMNN}}\|_2 = D_M(\mathbf{x}_i, \mathbf{x}_j)

Per-cell metrics: low-rank and diagonal
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The global metric weights the features the same way everywhere. In the per-cell modes a small
network predicts the metric of each cell from that cell's features, so the weighting can differ
between regions. There are two forms of the per-cell metric, selected by ``lmnn_mode``; both are
trained by one trainer
(:func:`~climclusterpy.clustering.lmnn.train_local_mahalanobis_lmnn`) with one loss, and differ
only in what the network predicts and in how that is turned into a distance.

.. list-table::
   :header-rows: 1
   :widths: 24 38 38

   * -
     - ``lmnn_mode="lowrank"`` (default)
     - ``lmnn_mode="diagonal"``
   * - Network output per cell
     - a factor :math:`\mathbf{L}_i \in \mathbb{R}^{d \times r}`
     - weights :math:`\mathbf{w}_i \in \mathbb{R}^{d}`
   * - Metric of the cell
     - :math:`\mathbf{M}_i = \mathbf{L}_i \mathbf{L}_i^\top` (positive semi-definite)
     - :math:`\mathbf{M}_i = \mathrm{diag}(\mathbf{w}_i)`
   * - Interaction between features
     - yes, through the off-diagonal entries
     - no: the feature axes are only rescaled
   * - Rank
     - ``rank`` (default 16, at most :math:`d`)
     - none; ``rank`` is refused
   * - Regulariser
     - :math:`\lambda_{\text{reg}} \|\mathbf{M}_i - \mathbf{I}\|_F^2`
     - none; ``lambda_reg`` is refused

The weights of the diagonal form are positive (a softplus) and normalized to sum to one.

**Distance.** The distance between two cells uses the mean of their two metrics, which makes it
symmetric:

.. math::

   D^2(\mathbf{x}_i, \mathbf{x}_j) = \tfrac{1}{2}\left[(\mathbf{x}_i - \mathbf{x}_j)^\top \mathbf{M}_i (\mathbf{x}_i - \mathbf{x}_j)
   + (\mathbf{x}_i - \mathbf{x}_j)^\top \mathbf{M}_j (\mathbf{x}_i - \mathbf{x}_j)\right].

For the low-rank form this is computed as :math:`\tfrac12(\|\mathbf{L}_i^\top \mathbf{d}\|^2 + \|\mathbf{L}_j^\top \mathbf{d}\|^2)` with
:math:`\mathbf{d} = \mathbf{x}_i - \mathbf{x}_j`, so no :math:`d \times d` matrix is formed; for the
diagonal form it is :math:`\tfrac12 \sum_k (w_{ik} + w_{jk})\, d_k^2`.
:func:`~climclusterpy.clustering.lmnn.compute_local_mahalanobis_distance_matrix` and
:func:`~climclusterpy.clustering.lmnn.compute_distance_matrix_local` return the full
:math:`n \times n` matrix of the two forms.

**Loss.** For each anchor :math:`i`, the target neighbours :math:`\mathcal{T}_i` are its nearest
same-class cells under the current metric, and the impostors :math:`\mathcal{I}_i` are the cells
of other classes:

.. math::

   \mathcal{L} = (1-\alpha)\,\overline{D^2(i, j)}_{j \in \mathcal{T}_i}
   + \alpha\,\overline{\max\!\big(0,\; \Delta + D^2(i, j) - D^2(i, l)\big)}_{j \in \mathcal{T}_i,\, l \in \mathcal{I}_i}
   + \lambda_{\text{reg}}\,\mathcal{L}_{\text{reg}},

a pull term, a linear hinge on squared distances and, for the low-rank form only, the identity
regulariser. The loss is computed within batches of cells. The number of targets per anchor
grows with the size of its class:

.. math::

   k_i = \min\!\big(n_i,\; k_{\max},\; \max(k_{\min},\; \lfloor \beta\,(n_i + 1) \rfloor)\big),

with :math:`n_i` the number of other cells of the anchor's class in the batch and defaults
:math:`k_{\min} = 3`, :math:`k_{\max} = 15`, :math:`\beta = 0.005`. The margin is
:math:`\Delta = \texttt{delta\_scale}\sqrt{d / d_0}` with ``delta_scale`` 1 and :math:`d_0`
(``margin_d0``) equal to the number of features unless set; :math:`\alpha` is 0.7 and
:math:`\lambda_{\text{reg}}` is :math:`10^{-3}`. Classes with fewer than 20 cells are oversampled
with a small jitter so that they can supply targets. Training uses AdamW with early stopping on a
20 % validation split; ``seed`` fixes every random stream.

**Networks.** Both networks are multilayer perceptrons with ReLU and dropout. The low-rank
network (:class:`~climclusterpy.clustering.lmnn.local.LocalMahalanobisMLP`) has two hidden layers
of :math:`\lfloor d \cdot \texttt{hidden\_width\_factor} \rfloor` units (factor 2 by default) and an output of
:math:`d \cdot r` units. The diagonal network
(:class:`~climclusterpy.clustering.lmnn.local.LocalWeightNetwork`) has hidden layers of
:math:`\max(16, \mathrm{round}(d \cdot \texttt{hidden\_width\_factor}))` and half that, and an output of :math:`d` units.

**Feature importance.** The package returns the trained model (``return_model=True``); from it, the importance of feature :math:`j` can be read, for the low-rank form, as
the diagonal of the mean metric :math:`[\tfrac1n \sum_i \mathbf{M}_i]_{jj}` and, for the diagonal form, as the mean weight
:math:`\tfrac1n \sum_i w_{ij}`. The off-diagonal entries of the mean low-rank metric show which
pairs of features act together.

Hierarchical Clustering
-----------------------

:mod:`climclusterpy.clustering.hierarchical` implements agglomerative hierarchical
clustering. ``linkage_method`` accepts the criteria of SciPy; the default is ``"complete"``.
Complete linkage bounds the largest distance within a group, so every member of a group is
similar to the cell simulated for it.

Linkage Methods
~~~~~~~~~~~~~~~

:func:`scipy.cluster.hierarchy.linkage` (called through
:func:`climclusterpy.clustering.compute_dendrogram`) computes the distance between two
groups :math:`C_1` and :math:`C_2` of sizes :math:`n_1` and :math:`n_2`. Ward linkage is
defined for Euclidean distances only. Complete and average linkage accept the precomputed
distance matrix of a learned per-cell distance.

.. math::

   d_{\text{Ward}}(C_1, C_2) = \sqrt{\frac{2 n_1 n_2}{n_1 + n_2}} \|\mathbf{c}_1 - \mathbf{c}_2\|_2,
   \qquad
   d_{\text{complete}}(C_1, C_2) = \max_{\mathbf{x} \in C_1,\, \mathbf{y} \in C_2} d(\mathbf{x}, \mathbf{y}),
   \qquad
   d_{\text{average}}(C_1, C_2) = \frac{1}{n_1 n_2} \sum_{\mathbf{x} \in C_1} \sum_{\mathbf{y} \in C_2} d(\mathbf{x}, \mathbf{y}),

where :math:`\mathbf{c}_k` is the centroid of :math:`C_k`.

**Dendrogram.** The linkage matrix :math:`\mathbf{Z} \in \mathbb{R}^{(n-1) \times 4}` holds, per
merge, the indices of the two merged groups, the merge distance and the size of the new group.
:func:`scipy.cluster.hierarchy.fcluster` with ``criterion='maxclust'`` cuts it into
:math:`K` groups, with labels :math:`1, \ldots, K`. One dendrogram serves every :math:`K`.

Cell Selection
--------------

``cell_selection`` sets which cells of a group the model simulates
(:mod:`climclusterpy.timeseries`; recipes in :doc:`../howto/cell_selection`). In the
*representative mode* one cell per group is simulated:

* ``"medoid"``: the member with the smallest summed distance to the other members of its
  group under the learned distance, :math:`i^* = \arg\min_{i \in C_k} \sum_{j \in C_k} d(i, j)`;
* ``"centroid"``: the member nearest the group mean :math:`\boldsymbol{\mu}_k` in feature
  space, :math:`i^* = \arg\min_{i \in C_k} \|\mathbf{x}_i - \boldsymbol{\mu}_k\|_2`;
* ``"auto"`` (default): the medoid when a learned distance exists, otherwise the centroid.

In the *random mode* (``"random"``) one member is drawn, :math:`i^* \sim
\mathrm{Uniform}(C_k)`. In the *distributed mode* (``"distributed"``)
``cells_per_cluster`` members are drawn at random and the group's ``npatch`` patches are
divided evenly between them. Both drawn modes compute no distance and no centroid.

Parallel Processing and Memory
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The number of workers is the ``n_jobs`` argument of :func:`~climclusterpy.create_clusters`
(``-1`` = all cores); ``preload_climate`` sets whether the climate is held in memory during
extraction. Environment variables tune how much is read at once and never change what is
computed (:ref:`environment-variables`). Intermediate results (a dendrogram, an ecoregion
assignment) are saved in the output folder and reused only when a fingerprint of their inputs
matches.

The Reduced Grid
----------------

:func:`climclusterpy.grid.build_reduced_grid` writes the selected cells as NetCDF input of
their own. Its per-group dataset carries ``cluster_label`` (the group, :math:`1, \ldots, K`),
``center_lat`` and ``center_lon`` (coordinates of the selected cell), ``n_cells`` (the size of
the group) and the climate variables, on the dimensions ``cluster`` (:math:`K`) and ``time``.
Besides the NetCDF files it writes the two mapping tables that reconstruction needs:

``cluster_id_mapping_<K>.csv``
   One row per original valid cell: ``original_cell_id``, ``new_cell_id``,
   ``cluster_index`` and ``cluster_label``.
``cluster_compact_map_<K>.csv``
   One row per group: ``cluster_label``, ``lat_index`` (its latitude row on the reduced
   grid) and ``cluster_index_start``, ``cluster_index_end`` (its first and last column in
   that row).

:func:`climclusterpy.io.convert_netcdf_to_clm` converts the NetCDF files to the binary
format LPJmL reads by calling LPJmL's ``cdf2clm`` and ``cdf2soil``, which are looked up in
``cdf2clm_path`` / ``cdf2soil_path``, ``tools_dir``, ``$LPJROOT/bin`` and ``PATH``, in that
order.

Reconstruction
--------------

:func:`climclusterpy.reconstruct_original_grid` gives every original cell the value
simulated for its group. Writing :math:`g(i)` for the group of original cell :math:`i`,
:math:`o_g(t)` for the output simulated for group :math:`g` and :math:`\hat{y}_i(t)` for the
reconstructed value,

.. math::

   \hat{y}_i(t) = o_{g(i)}(t) \quad \text{for every valid cell } i \text{ and time step } t,

and cells that are not valid stay missing. In the representative and random modes
:math:`o_g` is the output of the group's one simulated cell
(:func:`~climclusterpy.grid.reconstruct_output_netcdf`). In the distributed mode it is the
mean, or the median with ``aggregate="median"``, over the group's drawn cells, ignoring
missing values (:func:`~climclusterpy.grid.reconstruct_from_distributed`). Cells are matched
by group label through the mapping tables, never by coordinate.

.. _reconstruction-check:

Checking a reconstruction
~~~~~~~~~~~~~~~~~~~~~~~~~

**Why.** The reduced grid is a re-arrangement of the original one: groups are packed into
latitude rows, and when :math:`K` approaches the number of cells several groups share a row.
A reconstruction that took a value from a neighbouring group's column, or placed a value in
the wrong cell, would look plausible on a map. The error would then be attributed to the
clustering, which is judged by how closely the reconstructed field agrees with a full-grid
simulation. The checks below separate the two: if the mapping is exact, any remaining
difference comes from the grouping and the cell selection.

**What is checked.** Three things, in three places.

1. *Before anything is written*, every reconstruction checks that the inputs belong
   together. The ID mapping and the compact map must describe the same groups; the number of
   groups must equal the ``n_clusters`` attribute of the model output, when it has one;
   every group's columns must exist in the output; the output must hold no values in
   columns that no group owns (which would mean it comes from another run); and every
   mapped cell must exist on the original grid. A violation raises a ``ValueError`` that
   names the files and counts. A group whose cells are all missing in the output stays
   missing on the full grid, with a warning.
2. *After writing*, :func:`~climclusterpy.grid.validate_reconstruction_grid` compares the
   reconstructed file with the original grid. It returns ``True`` only if the variable is
   present, the latitude and longitude arrays have the original shape and values, and the
   cells that are missing are exactly the cells that are not valid on the original grid.
   On failure it returns ``False`` and logs which of the three failed.
3. *The mapping itself* is tested by the round-trip test of the test suite (marker
   ``roundtrip``, always run). It clusters a grid, writes a synthetic model output in which
   group :math:`g` has the known value :math:`10 g + t` at time step :math:`t`,
   reconstructs it, and asserts that every valid cell holds the value of its group and every invalid cell is
   missing.

**How it is computed: a small example.** Six valid cells with labels
:math:`g = (1, 1, 2, 3, 3, 3)` and a model output with one value per group at :math:`t = 0`:
:math:`o = (10, 20, 30)`. The reconstruction is :math:`\hat{y} = (10, 10, 20, 30, 30, 30)`.
The round-trip test compares, for every valid cell and time step, the reconstructed value
with the value of its group's column in the model output:

.. math::

   \max_{i,t} \left| \hat{y}_i(t) - o_{g(i)}(t) \right| \approx 0.

The comparison is ``numpy.allclose``, so it tolerates floating-point rounding and nothing
larger. Every cell of group 3 reads :math:`30`; had the reconstruction read the column of
group 2 for one of them, the difference would be :math:`10` and the test would fail. The test
also requires every cell outside the valid mask to be missing.

**What passes and what fails.** The round-trip test passes only when every valid cell matches its group's
value and every invalid cell is missing. The paper reports that the mapping reproduced
all 28 reduced grids it reconstructed (two clusterings, sixteen cluster counts from 7 to
60 678) bit for bit. The check does *not* measure how well the groups represent their cells:
that is the accuracy against a full-grid simulation described in the paper, computed in the
``climclusterpy-research`` repository.

**How to run it.**

.. code-block:: python

   from climclusterpy import reconstruct_original_grid
   from climclusterpy.grid import validate_reconstruction_grid

   full = reconstruct_original_grid("vegc.nc", clusters=clusters)   # step 1 runs inside
   assert validate_reconstruction_grid(full.path, clusters.registry, var_name="vegc")  # step 2

.. code-block:: console

   $ pytest -m roundtrip                       # step 3, on the synthetic data of the test suite
   $ python examples/example_4_reconstruct.py   # the same round trip as a script

Own model output can be checked the same way: the reconstructed value of every cell of a
group must equal the value in the reduced-grid output at that group's column, which a
``numpy`` comparison of the two files verifies directly.
