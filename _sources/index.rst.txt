climclusterpy
=============

.. image:: _static/logo-wordmark.svg
   :alt: climclusterpy
   :width: 420px

****Ecologically-informed clustering of climate and static fields for reduced model grids.**

``climclusterpy`` divides the cells of a model's grid into groups of similar climate and
static fields (soil, elevation, land cover, ...). The model is run on one or a few cells of
each group, written as a *reduced grid*, and every original cell then receives the output
simulated for its group. The input is any set of gridded climate fields and static fields,
under the names the model uses. The method is described in the accompanying paper.

Two calls do the whole job:

.. code-block:: python

   from climclusterpy import create_clusters, reconstruct_original_grid

   # 1. Reduce the grid: writes model-ready NetCDFs and the mapping CSVs.
   clusters = create_clusters(
       climate={"temperature": "/data/tas.nc", "precipitation": "/data/pr.nc"},
       static={"soil": ("/data/soil.nc", "categorical")},
       n_clusters=2000,
   )

   # ... run the model on clusters.netcdf_files ...

   # 2. Give every original cell the output simulated for its group.
   full = reconstruct_original_grid("vegc_output.nc", clusters=clusters)

``locally_weighted=True`` learns the distance between cells before clustering. The learned
distance is supervised by Köppen–Geiger classes computed from the climate input, by an
ecoregion map, or by the model's own output traits:

.. code-block:: python

   clusters = create_clusters(
       climate={"temperature": "/data/tas.nc", "precipitation": "/data/pr.nc"},
       n_clusters=2000,
       locally_weighted=True,
       supervision_data="/data/model_output/trait_grids",   # or a per-cell CSV
       supervision=["sla", "wooddens", "height", "biomass"],
   )

The input can also be built beforehand as a :class:`~climclusterpy.GenericInputs`. The
six-file input layout of LPJmL-FIT, the model the package was developed with, is accepted
as a directory (:doc:`howto/inputs`). :func:`~climclusterpy.load_clusters` restores the
result of ``create_clusters`` in a later session (:doc:`howto/reconstruct`).

The individual steps are available as functions too, for example
:func:`~climclusterpy.cluster_matrix` and :func:`~climclusterpy.compute_supervision`
(:doc:`reference/index`). Heavy dependencies are loaded only by the features that need them
(:doc:`howto/install`).
