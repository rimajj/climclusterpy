Methods

This page describes the algorithms and data transformations that climclusterpy implements, in the order in which a run applies them. It ends with the reduced grid and the check that a reconstruction is correct.

Data acquisition and preprocessing

Climate and static-field loading

The package reads NetCDF input with climclusterpy.data.loader (the fixed LPJmL-FIT file layout) and climclusterpy.data.generic_input (any named climate and static fields). Both share the characteristics below, and both align every field to one grid that the land mask or cell list defines.

Chunked processing:

The package loads climate datasets with Dask in chunks of configurable size (default 500 time steps):

ds = xr.open_dataset(path, chunks={"time": 500})

Chunking allows:

  • parallel computation across chunks,

  • memory-efficient processing of large datasets (>10 GB) and

  • lazy evaluation of array operations.

Memory optimization:

The package converts all float64 data variables to float32:

\[\text{Memory}_{\text{optimized}} = 0.5 \times \text{Memory}_{\text{original}}\]

This conversion keeps 7 significant digits, which is enough for climate data, and halves memory consumption.

Coordinate standardization:

The package processes latitude and longitude coordinates in three steps:

  1. It renames them to the standard names latitude and longitude.

  2. It rounds them to 5 decimal places (\(10^{-5}\) degrees ≈ 1.1 m spatial resolution).

  3. It validates grid compatibility across datasets.

The package resolves variable names through these synonyms (it uses a file with a single data variable whatever the variable is called):

precipitation: tpr, pr, precip, precipitation_flux, tp
temperature: TMean, tmean, tas, t2m, temp
radiation: SWR, rsds, SWdown, swdown, LWR, rlds, LWdown
humidity: hurs, humid, rh, relative_humidity

Grid compatibility validation:

The climclusterpy.data.coords.check_grid_compatibility() function checks spatial alignment:

\[\forall i,j: |\text{lat}^A_i - \text{lat}^B_i| < \epsilon \land |\text{lon}^A_j - \text{lon}^B_j| < \epsilon\]

where \(\epsilon = 10^{-5}\) degrees, i.e. the coordinates must be identical after rounding to 5 decimals. A climate input that is not on the grid of the land mask (or cell list, or first field) raises an error and is not regridded, so regrid it before loading. Static fields can sit on a slightly different grid, and the package then maps them onto the reference grid by nearest neighbour and warns.

Data registry

The climclusterpy.data.DataRegistry manages spatial grids and identifies valid cells.

Valid cell identification:

A boolean mask \(\mathbf{M} \in \{0,1\}^{n_{\text{lat}} \times n_{\text{lon}}}\) identifies valid cells. It is built from whatever defines the model’s cells: a land-mask file (non-zero and not missing), a list of cell coordinates, or, with neither, every cell where all fields have data. For the LPJmL-FIT file layout the mask is the soil code:

\[\begin{split}M_{ij} = \begin{cases} 1 & \text{if soil\_code}_{ij} \neq \text{sentinel} \land \neg \text{isnan}(\text{soil\_code}_{ij}) \\ 0 & \text{otherwise} \end{cases}\end{split}\]

The package detects missing values in a mask file or soil code in this order:

  1. NetCDF encoding attributes (_FillValue, missing_value)

  2. Common integer sentinels, when neither attribute is set: \(-9999, -999, 9999, -32768, -10^6\)

  3. NaN values in floating-point arrays

Flattening operation:

The climclusterpy.data.DataRegistry.flatten_on_valid() method projects multi-dimensional arrays onto the 1D valid cell space:

\[\mathbf{X}_{\text{flat}} = \text{extract}(\mathbf{X}_{\text{grid}}, \mathbf{M}) \in \mathbb{R}^{n_{\text{valid}} \times n_{\text{time}}}\]

where \(n_{\text{valid}} = \sum_{i,j} M_{ij}\).

This operation reduces memory by dropping invalid cells (ocean, missing data), speeds up computation by working on contiguous arrays, and keeps the spatial correspondence through the registry’s ID mapping.

Ecoregion assignment

The climclusterpy.supervision.ecoregions module assigns grid cells to ecological regions through spatial intersection.

Spatial join algorithm:

Given:

  • Ecoregion polygons \(\{P_1, P_2, \ldots, P_K\}\) with identifiers \(\{e_1, e_2, \ldots, e_K\}\)

  • Grid cell points \(\{\mathbf{p}_1, \mathbf{p}_2, \ldots, \mathbf{p}_n\}\) where \(\mathbf{p}_i = (\text{lat}_i, \text{lon}_i)\)

The assignment function is:

\[\begin{split}\text{ecoregion}(\mathbf{p}_i) = \begin{cases} e_k & \text{if } \mathbf{p}_i \cap P_k \neq \emptyset \\ \text{null} & \text{otherwise} \end{cases}\end{split}\]

Coordinate normalization:

Longitude coordinates are normalized to \([-180, 180)\):

\[\text{lon}_{\text{norm}} = ((\text{lon} + 180) \mod 360) - 180\]

This matches the convention of standard ecoregion shapefiles (e.g., Ecoregions2017 from Dinerstein et al., 2017).

Implementation:

The climclusterpy.supervision.assign_cells_to_ecoregions() function uses a vectorized GeoPandas spatial join:

matched = gpd.sjoin(
    points_gdf,
    ecoregions_gdf,
    how='left',
    predicate='intersects'
)

The intersects predicate (rather than within) includes cells that lie exactly on polygon boundaries, which maximizes spatial coverage.

Ecological feature summarization

The climclusterpy.features module turns climate time series into interpretable ecological summary statistics. Choose the features lists the columns that create_clusters() builds and explains how to choose them. create_clusters does not apply the ecology diagnostics and the block PCA below; they are building blocks.

Temperature features

For temperature time series \(\{T_1, T_2, \ldots, T_{n_t}\}\), climclusterpy.features.climate._summarize_temperature() computes the following statistics:

Annual mean:

\[\mu_T = \frac{1}{n_t} \sum_{t=1}^{n_t} T_t\]

Annual standard deviation:

\[\sigma_T = \sqrt{\frac{1}{n_t} \sum_{t=1}^{n_t} (T_t - \mu_T)^2}\]

Annual range:

\[R_T = \max_t(T_t) - \min_t(T_t)\]

Seasonality:

The monthly climatology averages each calendar month across all years:

\[\bar{T}_m = \frac{1}{n_y} \sum_{y=1}^{n_y} T_{y,m} \quad \text{for } m \in \{1, 2, \ldots, 12\}\]

Seasonality is the standard deviation of the monthly means:

\[S_T = \sqrt{\frac{1}{12} \sum_{m=1}^{12} (\bar{T}_m - \mu_T)^2}\]

It measures the amplitude of seasonal temperature variation.

Precipitation features

For precipitation time series \(\{P_1, P_2, \ldots, P_{n_t}\}\), climclusterpy.features.climate._summarize_precipitation() computes:

Annual mean:

\[\mu_P = \frac{1}{n_t} \sum_{t=1}^{n_t} P_t\]

Coefficient of variation:

\[\text{CV}_P = \frac{\sigma_P}{\mu_P}\]

where \(\sigma_P\) is the temporal standard deviation. CV measures relative precipitation variability.

Wet-Day frequency:

\[f_{\text{wet}} = \frac{1}{n_t} \sum_{t=1}^{n_t} \mathbb{1}(P_t > \theta)\]

where \(\theta = 1\) mm is the wet-day threshold and \(\mathbb{1}(\cdot)\) is the indicator function.

Maximum monthly precipitation:

\[P_{\max} = \max_{t \in \{1, \ldots, n_t\}} P_t\]

It captures extreme precipitation events.

Radiation features

For shortwave (\(R_s\)) and longwave (\(R_l\)) radiation, climclusterpy.features.climate._summarize_radiation() computes:

\[\begin{split}\begin{align} \mu_R &= \frac{1}{n_t} \sum_{t=1}^{n_t} R_t \quad \text{(annual mean)} \\ \sigma_R &= \sqrt{\frac{1}{n_t} \sum_{t=1}^{n_t} (R_t - \mu_R)^2} \quad \text{(annual std)} \\ A_R &= \max_t(R_t) - \min_t(R_t) \quad \text{(seasonal amplitude)} \end{align}\end{split}\]

Humidity features

For relative humidity \(\{H_1, H_2, \ldots, H_{n_t}\}\), climclusterpy.features.climate._summarize_humidity() computes:

\[\begin{split}\begin{align} \mu_H &= \frac{1}{n_t} \sum_{t=1}^{n_t} H_t \quad \text{(annual mean)} \\ \sigma_H &= \sqrt{\frac{1}{n_t} \sum_{t=1}^{n_t} (H_t - \mu_H)^2} \quad \text{(annual std)} \\ H_{\min} &= \min_t(H_t) \quad \text{(dry-season minimum)} \end{align}\end{split}\]

Static-field features

Every static field (soil, elevation, land cover, …) is declared "continuous" (kept as one numeric feature) or "categorical" (an integer class code, one-hot encoded so all classes are equally far apart). For the LPJmL-FIT layout, climclusterpy.features.summarize_soil_features() extracts the soil depth as a continuous feature and the soil code as a categorical one.

For a static field with a time dimension, the first time step is used, under the assumption of temporal invariance.

Köppen–Geiger diagnostic scalar features

Eight continuous KG-diagnostic scalar features are computed directly from the monthly climatologies and latitude by climclusterpy.features.compute_kg_diagnostic_features(), capturing the core rule quantities used by Köppen–Geiger classification:

  • kg_diag_T_cold, kg_diag_T_warm: Coldest and warmest month temperature

  • kg_diag_P_dry_min, kg_diag_P_wet_max: Driest and wettest month precipitation

  • kg_diag_P_dry_summer, kg_diag_P_dry_winter: Hemisphere-aware dry-season precipitation minima

  • kg_diag_P_seasonality_ratio: Wettest-to-driest precipitation ratio, clipped to \([1, 100]\)

  • kg_diag_aridity_index: Aridity index offset from the KG threshold \(P_{\text{ann}} - (2 T_{\text{ann}} + 28)\)

These kg_diag_ features are protected from removal in the filtering stages.

Ecology diagnostic features

Thirteen ecophysiological features are computed from the monthly climatologies by climclusterpy.features.compute_all_ecology_diagnostic_features(), capturing water-balance characteristics and thermal thresholds relevant to vegetation dynamics. These eco_diag_ features are protected from removal during correlation and PCA filtering stages.

Vapour pressure deficit (VPD):

Monthly VPD is computed from monthly temperature \(\bar{T}_m\) and relative humidity \(\bar{H}_m\):

\[\mathrm{VPD}_m = e_s(\bar{T}_m)\,(1 - \bar{H}_m / 100), \qquad e_s(T) = 0.6108 \exp\!\left(\frac{17.27\,T}{T + 237.3}\right)\ \text{[kPa]}\]

Three features are derived:

  • eco_diag_vpd_mean: Annual mean \(\overline{\mathrm{VPD}} = \tfrac{1}{12}\sum_m \mathrm{VPD}_m\)

  • eco_diag_vpd_max_monthly: Maximum monthly value \(\max_m \mathrm{VPD}_m\)

  • eco_diag_vpd_stress_months: Count of months with \(\mathrm{VPD}_m > 1.5\) kPa

Growing degree days (GDD):

Thermal accumulation indices computed from monthly temperature:

\[\mathrm{GDD}_b = \sum_{m=1}^{12} \max(0,\;\bar{T}_m - b)\,\cdot\, n_{\mathrm{days},m}\]

  • eco_diag_gdd_5: Base \(b = 5\,°\text{C}\) (cool-season crops, boreal vegetation)

  • eco_diag_gdd_10: Base \(b = 10\,°\text{C}\) (warm-season crops, temperate vegetation)

Frost-Free days:

\[F = \sum_{m=1}^{12} \mathbb{1}(\bar{T}_m > 0)\,\cdot\, n_{\mathrm{days},m}\]

  • eco_diag_frost_free_days: Distinguishes transitional climates where frost occurrence is intermittent.

Potential evapotranspiration and moisture balance:

Monthly PET is estimated via the Priestley–Taylor method (where radiation data are available) or Thornthwaite approximation:

  • eco_diag_pet_mean: Annual mean PET (mm day-1)

  • eco_diag_p_pet_ratio: Annual precipitation-to-PET ratio \(\overline{P}/\overline{\mathrm{PET}}\) (moisture index)

  • eco_diag_water_deficit_months: Count of months where \(\bar{P}_m < \mathrm{PET}_m\)

Dry spells:

Consecutive runs of months with \(\bar{P}_m < 30\) mm are identified:

  • eco_diag_dry_spell_max: Maximum spell length across the annual cycle

  • eco_diag_dry_spell_mean: Mean spell length

These capture the persistence of dry seasons beyond their total duration.

Precipitation intensity and seasonality:

  • eco_diag_precip_intensity_wet_days: Mean precipitation per wet month \(\bar{P}_{\mathrm{wet}} = \sum_m \bar{P}_m \mathbb{1}(\bar{P}_m > 30) / \sum_m \mathbb{1}(\bar{P}_m > 30)\)

  • eco_diag_precip_wettest_quarter_frac: Fraction of annual precipitation falling in the wettest quarter \(f_{\mathrm{wq}} = P_{\mathrm{wq}} / P_{\mathrm{ann}}\)

Feature combination

climclusterpy.features.combine_features() merges climate and soil DataFrames through an inner join on cell_id, latitude, and longitude, producing the raw feature matrix:

\[\mathbf{X}_{\text{raw}} \in \mathbb{R}^{n \times p}\]

where \(n\) is the number of cells and \(p\) is the total feature count (typically \(p \approx 20\)–50 before filtering).

Feature standardization and filtering

Z-score standardization

climclusterpy.features.standardize_features() applies z-score transformation:

\[\mathbf{X}_{ij}^{\text{std}} = \frac{\mathbf{X}_{ij}^{\text{raw}} - \mu_j}{\sigma_j}\]

where:

\[\begin{split}\begin{align} \mu_j &= \frac{1}{n} \sum_{i=1}^n \mathbf{X}_{ij}^{\text{raw}} \\ \sigma_j &= \sqrt{\frac{1}{n} \sum_{i=1}^n (\mathbf{X}_{ij}^{\text{raw}} - \mu_j)^2} \end{align}\end{split}\]

This ensures:

  • Zero mean: \(\mathbb{E}[\mathbf{X}_{:j}^{\text{std}}] = 0\)

  • Unit variance: \(\text{Var}(\mathbf{X}_{:j}^{\text{std}}) = 1\)

  • Comparability across features with disparate units

Correlation-based feature removal

climclusterpy.features.remove_correlated_features() eliminates highly correlated features to mitigate multicollinearity.

Correlation computation:

The package computes Spearman rank correlation coefficients for all feature pairs:

\[\rho_{jk} = \text{corr}_{\text{Spearman}}(\mathbf{X}_{:j}^{\text{std}}, \mathbf{X}_{:k}^{\text{std}})\]

The package uses Spearman instead of Pearson correlation because Spearman captures monotonic (not only linear) relationships and is less sensitive to outliers.

Iterative removal:

For each pair \((j, k)\) satisfying \(|\rho_{jk}| > \theta_{\text{corr}}\) (default \(\theta_{\text{corr}} = 0.9\)):

  1. Compute mean absolute correlation for each feature:

    \[\bar{\rho}_j = \frac{1}{p-1} \sum_{k \neq j} |\rho_{jk}|\]

  2. Remove the feature with higher \(\bar{\rho}\):

    \[\text{remove}(j) \text{ if } \bar{\rho}_j > \bar{\rho}_k\]

This greedy strategy keeps the features with lower overall correlation.

Soil features are excluded from correlation analysis as they represent static, discrete properties.

Block PCA compression of monthly profiles

climclusterpy.features.apply_block_pca_compression() reduces redundancy in the 12-dimensional monthly climatology profiles while preserving seasonal structure.

A separate PCA is fit to the temperature-monthly block (tas_month_01..12) and the precipitation-monthly block (pr_month_01..12). For each block, the minimum number of components explaining at least 99% of within-block variance is retained. Raw monthly columns are dropped and replaced by whitened PC scores:

\[\tilde{z}_{ik} = \frac{z_{ik}}{\sqrt{\lambda_k^{\text{block}}}}\]

where \(z_{ik}\) is the raw PCA score of cell \(i\) on block-PC \(k\) and \(\lambda_k^{\text{block}}\) is the corresponding eigenvalue (explained variance). Whitening ensures that all PC scores have unit variance, consistent with the z-scored summary features, and prevents high-variance leading PCs from dominating the downstream LMNN metric.

The resulting features are named tas_month_PC1..N_T and pr_month_PC1..N_P. Fitted PCA objects are cached to disk (block_pca_tas.pkl, block_pca_pr.pkl) to ensure consistent reuse across runs.

PCA-based diagnostic filtering

climclusterpy.features.diagnostic_pca_filter() uses PCA to identify low-contribution features without dimensionality reduction.

Algorithm:

  1. Compute full PCA decomposition of \(\mathbf{X}^{\text{decorr}}\):

    \[\mathbf{X}^{\text{decorr}} = \sum_{i=1}^p \lambda_i \mathbf{u}_i \mathbf{v}_i^\top\]

    where \(\lambda_i\) are eigenvalues (explained variances) and \(\mathbf{v}_i\) are principal component loadings.

  2. Determine minimum \(m\) satisfying variance threshold \(\theta_{\text{var}} = 0.95\):

    \[m = \min \left\{ k : \sum_{i=1}^k \lambda_i \geq \theta_{\text{var}} \sum_{i=1}^p \lambda_i \right\}\]

  3. For each original feature \(j\), compute total absolute contribution across the first \(m\) components:

    \[C_j = \frac{1}{m} \sum_{i=1}^m |v_{ij}|\]

  4. Normalize contributions:

    \[C_j^{\text{norm}} = \frac{C_j}{\sum_{k=1}^p C_k}\]

  5. Remove features with \(C_j^{\text{norm}} < \theta_{\text{contrib}}\) (default \(\theta_{\text{contrib}} = 0.01\)).

This retains features substantially contributing to the dominant variance modes while eliminating redundant or low-information variables.

Output:

The final feature set \(\mathbf{X} \in \mathbb{R}^{n \times d}\) (where \(d \ll p\)) combines:

  • Filtered climate features (correlation + PCA filtered)

  • Unfiltered soil features (preserved as static environmental descriptors)

Large margin nearest neighbor (LMNN) metric learning

The climclusterpy.clustering module learns a distance from a supervision signal in one of three modes (lmnn_mode): "global", and the per-cell "lowrank" and "diagonal" forms.

Global LMNN

climclusterpy.clustering.lmnn implements classic LMNN (Weinberger & Saul, 2009) with a single global Mahalanobis distance.

Mahalanobis distance:

The learned metric is defined by transformation matrix \(\mathbf{L} \in \mathbb{R}^{d' \times d}\):

\[D_M(\mathbf{x}_i, \mathbf{x}_j) = \sqrt{(\mathbf{x}_i - \mathbf{x}_j)^\top \mathbf{M} (\mathbf{x}_i - \mathbf{x}_j)}\]

where:

\[\mathbf{M} = \mathbf{L}^\top \mathbf{L} \in \mathbb{R}^{d \times d}\]

is the learned Mahalanobis matrix.

Optimization objective:

LMNN minimizes:

\[\mathcal{L}_{\text{LMNN}} = (1-\mu) \mathcal{L}_{\text{pull}} + \mu \mathcal{L}_{\text{margin}}\]

where:

\[\begin{split}\begin{align} \mathcal{L}_{\text{pull}} &= \sum_{i=1}^n \sum_{j \in \mathcal{T}_i} D_M^2(\mathbf{x}_i, \mathbf{x}_j) \\ \mathcal{L}_{\text{margin}} &= \sum_{i=1}^n \sum_{j \in \mathcal{T}_i} \sum_{l \notin \mathcal{T}_i} \xi_{ijl} \end{align}\end{split}\]

subject to:

\[D_M^2(\mathbf{x}_i, \mathbf{x}_l) - D_M^2(\mathbf{x}_i, \mathbf{x}_j) \geq 1 - \xi_{ijl}, \quad \xi_{ijl} \geq 0\]

Here:

  • \(\mathcal{T}_i\) = set of \(k\) nearest same-ecoregion neighbors (target neighbors)

  • \(l\) indexes different-ecoregion cells (impostors)

  • \(\mu \in [0,1]\) balances pull vs. margin terms

  • \(\xi_{ijl}\) are slack variables for soft constraints

Interpretation:

  • The pull term minimizes distances to same-ecoregion neighbors.

  • The margin term enforces separation from different-ecoregion cells with margin = 1.

Feature importance:

Feature importance is extracted from the diagonal of \(\mathbf{M}\):

\[I_j = M_{jj}\]

with normalization:

\[I_j^{\text{norm}} = \frac{I_j}{\sum_{k=1}^d I_k}\]

Large values indicate features strongly influencing the learned metric.

Feature transformation:

climclusterpy.clustering.lmnn.transform_features() projects data into the learned metric space:

\[\mathbf{X}^{\text{LMNN}} = \mathbf{X} \mathbf{L}^\top\]

In this space, Euclidean distance equals the original Mahalanobis distance:

\[\|\mathbf{x}_i^{\text{LMNN}} - \mathbf{x}_j^{\text{LMNN}}\|_2 = D_M(\mathbf{x}_i, \mathbf{x}_j)\]

Per-cell metrics: low-rank and diagonal

The global metric weights the features the same way everywhere. In the per-cell modes a small network predicts the metric of each cell from that cell’s features, so the weighting can differ between regions. There are two forms of the per-cell metric, selected by lmnn_mode; both are trained by one trainer (train_local_mahalanobis_lmnn()) with one loss, and differ only in what the network predicts and in how that is turned into a distance.

lmnn_mode="lowrank" (default)

lmnn_mode="diagonal"

Network output per cell

a factor \(\mathbf{L}_i \in \mathbb{R}^{d \times r}\)

weights \(\mathbf{w}_i \in \mathbb{R}^{d}\)

Metric of the cell

\(\mathbf{M}_i = \mathbf{L}_i \mathbf{L}_i^\top\) (positive semi-definite)

\(\mathbf{M}_i = \mathrm{diag}(\mathbf{w}_i)\)

Interaction between features

yes, through the off-diagonal entries

no: the feature axes are only rescaled

Rank

rank (default 16, at most \(d\))

none; rank is refused

Regulariser

\(\lambda_{\text{reg}} \|\mathbf{M}_i - \mathbf{I}\|_F^2\)

none; lambda_reg is refused

The weights of the diagonal form are positive (a softplus) and normalized to sum to one.

Distance: The distance between two cells uses the mean of their two metrics, which makes it symmetric:

\[D^2(\mathbf{x}_i, \mathbf{x}_j) = \tfrac{1}{2}\left[(\mathbf{x}_i - \mathbf{x}_j)^\top \mathbf{M}_i (\mathbf{x}_i - \mathbf{x}_j) + (\mathbf{x}_i - \mathbf{x}_j)^\top \mathbf{M}_j (\mathbf{x}_i - \mathbf{x}_j)\right].\]

For the low-rank form this is computed as \(\tfrac12(\|\mathbf{L}_i^\top \mathbf{d}\|^2 + \|\mathbf{L}_j^\top \mathbf{d}\|^2)\) with \(\mathbf{d} = \mathbf{x}_i - \mathbf{x}_j\), so no \(d \times d\) matrix is formed; for the diagonal form it is \(\tfrac12 \sum_k (w_{ik} + w_{jk})\, d_k^2\). compute_local_mahalanobis_distance_matrix() and compute_distance_matrix_local() return the full \(n \times n\) matrix of the two forms.

Loss: For each anchor \(i\), the target neighbours \(\mathcal{T}_i\) are its nearest same-class cells under the current metric, and the impostors \(\mathcal{I}_i\) are the cells of other classes:

\[\mathcal{L} = (1-\alpha)\,\overline{D^2(i, j)}_{j \in \mathcal{T}_i} + \alpha\,\overline{\max\!\big(0,\; \Delta + D^2(i, j) - D^2(i, l)\big)}_{j \in \mathcal{T}_i,\, l \in \mathcal{I}_i} + \lambda_{\text{reg}}\,\mathcal{L}_{\text{reg}},\]

a pull term, a linear hinge on squared distances and, for the low-rank form only, the identity regulariser. The loss is computed within batches of cells. The number of targets per anchor grows with the size of its class:

\[k_i = \min\!\big(n_i,\; k_{\max},\; \max(k_{\min},\; \lfloor \beta\,(n_i + 1) \rfloor)\big),\]

with \(n_i\) the number of other cells of the anchor’s class in the batch and defaults \(k_{\min} = 3\), \(k_{\max} = 15\), \(\beta = 0.005\). The margin is \(\Delta = \texttt{delta\_scale}\sqrt{d / d_0}\) with delta_scale 1 and \(d_0\) (margin_d0) equal to the number of features unless set; \(\alpha\) is 0.7 and \(\lambda_{\text{reg}}\) is \(10^{-3}\). Classes with fewer than 20 cells are oversampled with a small jitter so that they can supply targets. Training uses AdamW with early stopping on a 20 % validation split; seed fixes every random stream.

Networks: Both networks are multilayer perceptrons with ReLU and dropout. The low-rank network (LocalMahalanobisMLP) has two hidden layers of \(\lfloor d \cdot \texttt{hidden\_width\_factor} \rfloor\) units (factor 2 by default) and an output of \(d \cdot r\) units. The diagonal network (LocalWeightNetwork) has hidden layers of \(\max(16, \mathrm{round}(d \cdot \texttt{hidden\_width\_factor}))\) and half that, and an output of \(d\) units.

Feature importance: The package returns the trained model (return_model=True); from it, the importance of feature \(j\) can be read, for the low-rank form, as the diagonal of the mean metric \([\tfrac1n \sum_i \mathbf{M}_i]_{jj}\) and, for the diagonal form, as the mean weight \(\tfrac1n \sum_i w_{ij}\). The off-diagonal entries of the mean low-rank metric show which pairs of features act together.

Hierarchical clustering

climclusterpy.clustering.hierarchical implements agglomerative hierarchical clustering. linkage_method accepts the criteria of SciPy; the default is "complete". Complete linkage bounds the largest distance within a group, so every member of a group is similar to the cell simulated for it.

Linkage methods

scipy.cluster.hierarchy.linkage() (called through climclusterpy.clustering.compute_dendrogram()) computes the distance between two groups \(C_1\) and \(C_2\) of sizes \(n_1\) and \(n_2\). Ward linkage is defined for Euclidean distances only. Complete and average linkage accept the precomputed distance matrix of a learned per-cell distance.

\[d_{\text{Ward}}(C_1, C_2) = \sqrt{\frac{2 n_1 n_2}{n_1 + n_2}} \|\mathbf{c}_1 - \mathbf{c}_2\|_2, \qquad d_{\text{complete}}(C_1, C_2) = \max_{\mathbf{x} \in C_1,\, \mathbf{y} \in C_2} d(\mathbf{x}, \mathbf{y}), \qquad d_{\text{average}}(C_1, C_2) = \frac{1}{n_1 n_2} \sum_{\mathbf{x} \in C_1} \sum_{\mathbf{y} \in C_2} d(\mathbf{x}, \mathbf{y}),\]

where \(\mathbf{c}_k\) is the centroid of \(C_k\).

The dendrogram: the linkage matrix \(\mathbf{Z} \in \mathbb{R}^{(n-1) \times 4}\) holds, per merge, the indices of the two merged groups, the merge distance and the size of the new group. scipy.cluster.hierarchy.fcluster() with criterion='maxclust' cuts it into \(K\) groups, with labels \(1, \ldots, K\). One dendrogram serves every \(K\).

Cell selection

cell_selection sets which cells of a group the model simulates (climclusterpy.timeseries; recipes in Choose the simulated cells). In the representative mode one cell per group is simulated:

  • "medoid": the member with the smallest summed distance to the other members of its group under the learned distance, \(i^* = \arg\min_{i \in C_k} \sum_{j \in C_k} d(i, j)\);

  • "centroid": the member nearest the group mean \(\boldsymbol{\mu}_k\) in feature space, \(i^* = \arg\min_{i \in C_k} \|\mathbf{x}_i - \boldsymbol{\mu}_k\|_2\);

  • "auto" (default): the medoid when a learned distance exists, otherwise the centroid.

In the random mode ("random") one member is drawn, \(i^* \sim \mathrm{Uniform}(C_k)\). In the distributed mode ("distributed") cells_per_cluster members are drawn at random and the group’s npatch patches are divided evenly between them. Both drawn modes compute no distance and no centroid.

Parallel processing and memory

The number of workers is the n_jobs argument of create_clusters() (-1 = all cores); preload_climate sets whether the climate is held in memory during extraction. Environment variables tune how much is read at once and never change what is computed (Environment variables). Intermediate results (a dendrogram, an ecoregion assignment) are saved in the output folder and reused only when a fingerprint of their inputs matches.

The reduced grid

climclusterpy.grid.build_reduced_grid() writes the selected cells as NetCDF input of their own. Its per-group dataset carries cluster_label (the group, \(1, \ldots, K\)), center_lat and center_lon (coordinates of the selected cell), n_cells (the size of the group) and the climate variables, on the dimensions cluster (\(K\)) and time. Besides the NetCDF files it writes the two mapping tables that reconstruction needs:

cluster_id_mapping_<K>.csv

One row per original valid cell: original_cell_id, new_cell_id, cluster_index and cluster_label.

cluster_compact_map_<K>.csv

One row per group: cluster_label, lat_index (its latitude row on the reduced grid) and cluster_index_start, cluster_index_end (its first and last column in that row).

climclusterpy.io.convert_netcdf_to_clm() converts the NetCDF files to the binary format LPJmL reads by calling LPJmL’s cdf2clm and cdf2soil, which are looked up in cdf2clm_path / cdf2soil_path, tools_dir, $LPJROOT/bin and PATH, in that order.

Reconstruction

climclusterpy.reconstruct_original_grid() gives every original cell the value simulated for its group. Writing \(g(i)\) for the group of original cell \(i\), \(o_g(t)\) for the output simulated for group \(g\) and \(\hat{y}_i(t)\) for the reconstructed value,

\[\hat{y}_i(t) = o_{g(i)}(t) \quad \text{for every valid cell } i \text{ and time step } t,\]

and cells that are not valid stay missing. In the representative and random modes \(o_g\) is the output of the group’s one simulated cell (reconstruct_output_netcdf()). In the distributed mode it is the mean, or the median with aggregate="median", over the group’s drawn cells, ignoring missing values (reconstruct_from_distributed()). Cells are matched by group label through the mapping tables, never by coordinate.

Checking a reconstruction

Why check: the reduced grid is a re-arrangement of the original one: groups are packed into latitude rows, and when \(K\) approaches the number of cells several groups share a row. A reconstruction that took a value from a neighbouring group’s column, or placed a value in the wrong cell, would look plausible on a map. The error would then be attributed to the clustering, which is judged by how closely the reconstructed field agrees with a full-grid simulation. The checks below separate the two: if the mapping is exact, any remaining difference comes from the grouping and the cell selection.

What is checked: three things, in three places.

  1. Before anything is written, every reconstruction checks that the inputs belong together. The ID mapping and the compact map must describe the same groups; the number of groups must equal the n_clusters attribute of the model output, when it has one; every group’s columns must exist in the output; the output must hold no values in columns that no group owns (which would mean it comes from another run); and every mapped cell must exist on the original grid. A violation raises a ValueError that names the files and counts. A group whose cells are all missing in the output stays missing on the full grid, with a warning.

  2. After writing, validate_reconstruction_grid() compares the reconstructed file with the original grid. It returns True only if the variable is present, the latitude and longitude arrays have the original shape and values, and the cells that are missing are exactly the cells that are not valid on the original grid. On failure it returns False and logs which of the three failed.

  3. The mapping itself is tested by the round-trip test of the test suite (marker roundtrip, always run). It clusters a grid, writes a synthetic model output in which group \(g\) has the known value \(10 g + t\) at time step \(t\), reconstructs it, and asserts that every valid cell holds the value of its group and every invalid cell is missing.

How it is computed, in a small example: six valid cells with labels \(g = (1, 1, 2, 3, 3, 3)\) and a model output with one value per group at \(t = 0\): \(o = (10, 20, 30)\). The reconstruction is \(\hat{y} = (10, 10, 20, 30, 30, 30)\). The round-trip test compares, for every valid cell and time step, the reconstructed value with the value of its group’s column in the model output:

\[\max_{i,t} \left| \hat{y}_i(t) - o_{g(i)}(t) \right| \approx 0.\]

The comparison is numpy.allclose, so it tolerates floating-point rounding and nothing larger. Every cell of group 3 reads \(30\); had the reconstruction read the column of group 2 for one of them, the difference would be \(10\) and the test would fail. The test also requires every cell outside the valid mask to be missing.

What passes and what fails: the round-trip test passes only when every valid cell matches its group’s value and every invalid cell is missing. The paper reports that the mapping reproduced all 28 reduced grids it reconstructed (two clusterings, sixteen cluster counts from 7 to 60 678) bit for bit. The check does not measure how well the groups represent their cells: that is the accuracy against a full-grid simulation described in the paper, computed in the climclusterpy-research repository.

To run the checks:

from climclusterpy import reconstruct_original_grid
from climclusterpy.grid import validate_reconstruction_grid

full = reconstruct_original_grid("vegc.nc", clusters=clusters)   # step 1 runs inside
assert validate_reconstruction_grid(full.path, clusters.registry, var_name="vegc")  # step 2

$ pytest -m roundtrip                       # step 3, on the synthetic data of the test suite
$ python examples/example_4_reconstruct.py   # the same round trip as a script

You can check your own model output the same way. The reconstructed value of every cell of a group must equal the value in the reduced-grid output at that group’s column, and a numpy comparison of the two files verifies this directly.
