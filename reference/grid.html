Grid building & reconstruction

Write per-cluster output to NetCDF on the reduced (artificial) grid, and project it back onto the full original grid. reconstruct_original_grid() dispatches over the two reconstruction functions below; see Reconstruct the original grid for which mapping files each needs.

create_clusters() and create_regions() call these for you. You need them directly only when you build the per-cluster timeseries yourself, or want to check where the cells landed.

Where each reduced cell is placed

Every reduced-grid cell carries the climate of one real cell. These functions decide the coordinates it is written at. The coordinates matter to the model because latitude sets day length.

Function

What it does

build_reduced_grid()

Recommended. Places each cell at the coordinates of the cell whose climate it carries, on the source grid’s own latitude spacing, writes the NetCDFs and mapping CSVs, then re-opens what it wrote and fails if the axes are not uniform or a cell was displaced.

create_native_grid_from_dataset()

The placement step of build_reduced_grid() on its own: returns the coordinates, writes nothing but the placement records.

create_regular_grid_from_dataset()

The older layout: places each cell at its cluster’s centre latitude (the member nearest the cluster’s median absolute latitude) on a lattice found by calculate_grid_parameters(). That is generally not the latitude of the cell whose climate it carries, and on real global cluster sets the two differ by up to 107°. Use it only when the latitudes genuinely do not lie on a regular lattice.

Note

In this version create_clusters() uses build_reduced_grid() for representative="random", writes "distributed" cells at their own positions with write_distributed_grid(), but still uses the centre-latitude layout of create_regular_grid_from_dataset() for "medoid" and "centroid". For those two, latitude_adjustments_<K>.csv in the output folder records each cluster’s centre latitude and the latitude it was written at — not the representative cell’s own latitude, which is in selected_cells_<K>.csv. Compare the two files to see how far a cell was moved.

build_reduced_grid(timeseries_dataset, output_dir, *, source_spacing, labels_csv=None, n_repeat=1, npatch=1, timeseries_type='representative', aggregation_type='clustering', cluster_method=None, artifacts_dir=None, id_mapping_file=None, lat_anchor=None, lon_origin=None, overwrite=True)[source]

Write a model-ready reduced grid with every cell where its climate came from.

One call for the build half of the round trip: it places the cells (create_native_grid_from_dataset()), writes one NetCDF per forcing variable plus the mapping CSVs the projection back reads (create_cluster_nc_files()), and then re-opens what it wrote to check the guarantees on the artifact rather than on the intent.

The other half is reconstruct_original_grid(), which needs nothing from this function but the two CSVs: it places values by cluster label and row index, never by coordinate, so where a cell sits changes the science but not the projection.

Parameters:

  • timeseries_dataset (xarray.Dataset) – One entry per cluster, carrying cluster_label, the representative cell’s latitude/longitude, time, and the forcing variables to write.

  • output_dir (str) – Where the NetCDFs go.

  • source_spacing (float) – The source grid’s cell size in degrees (0.5 for a half-degree grid).

  • labels_csv (str, optional) – The cell_id,cluster_label table for the whole original grid. Needed to write cluster_id_mapping_{K}.csv, without which the projection back has no way to know which original cells a cluster stands for.

  • n_repeat (int, optional) – Cells written per cluster, and patches per cluster, as create_cluster_nc_files() defines them.

  • npatch (int, optional) – Cells written per cluster, and patches per cluster, as create_cluster_nc_files() defines them.

  • timeseries_type (str, optional) – Carried into the output filenames unchanged.

  • aggregation_type (str, optional) – Carried into the output filenames unchanged.

  • cluster_method (str, optional) – Carried into the output filenames unchanged.

  • artifacts_dir (str, optional) – Where the CSVs go; defaults to output_dir.

  • id_mapping_file (str, optional) – An existing cluster_id_mapping CSV to use instead of writing one.

  • lat_anchor (float, optional) – Passed to create_native_grid_from_dataset().

  • lon_origin (float, optional) – Passed to create_native_grid_from_dataset().

  • overwrite (bool, optional) – When False, a variable whose NetCDF already exists and is non-empty is skipped.

Returns:

Variable name to written path, plus "__id_mapping__" and "__placement__".

Return type:

dict

Raises:

ValueError – If the placement cannot be made faithfully (see create_native_grid_from_dataset()), or if the grid that was written does not carry the placement it was told to — a uniform axis at the source spacing, one slot block per cluster, and a compact map that points at those blocks.

create_native_grid_from_dataset(ds, n_repeat=1, output_dir=None, *, source_spacing, lat_anchor=None, lon_origin=None)[source]

Place every cluster at its representative cell’s coordinates, on the source lattice.

The drop-in alternative to create_regular_grid_from_dataset(): same six-field return, no spacing search, and no free parameter to tune — the lattice is the source grid’s, and the placement is the cell’s own.

Parameters:

  • ds (xarray.Dataset) – The cluster timeseries dataset, one entry per cluster along cluster, carrying cluster_label and the representative cell’s latitude/longitude. This is what extract_representative_cells() writes.

  • n_repeat (int, optional) – Cells written per cluster (default 1). Each cluster gets n_repeat adjacent columns, so a row’s width is the busiest cluster count times this.

  • output_dir (str, optional) – Where to write the two placement records. When given, cell_placement_{K}.csv (every cluster’s true coordinates, the slot it occupies, and its displacement — all zero by construction) and latitude_adjustments_{K}.csv (the same thing in the column names the reconstruction path already reads) land here. Writing them is what keeps the fictional longitude axis admissible: the true coordinates are recorded even though the axis cannot carry them.

  • source_spacing (float) – The source grid’s cell size in degrees — 0.5 for a half-degree grid. Required, and deliberately not inferred: guessing it is exactly the silent decision this construction exists to remove.

  • lat_anchor (float, optional) – The real source latitude the lattice is anchored on. Defaults to the southernmost representative latitude, which is a source latitude by definition.

  • lon_origin (float, optional) – Where the packed column block starts. Defaults to the westernmost representative longitude, shifted west only as far as needed to keep the block inside ±180°.

Returns:

Hand it to create_cluster_nc_files() as precomputed_grid=, with lon_spacing=source_spacing, or let build_reduced_grid() do both.

Return type:

NativePlacement

Raises:

ValueError – If any representative latitude does not already lie on the source lattice, if either declared cell size would differ from source_spacing, if the packed block cannot fit inside ±180°, or if the dataset does not carry one coordinate pair per cluster. Every one of these is a silent-wrong-answer condition downstream, so none of them warns.

Examples

>>> import numpy as np, xarray as xr
>>> ds = xr.Dataset(
...     {
...         "cluster_label": ("cluster", np.array([1, 2, 3])),
...         "latitude": ("cluster", np.array([-0.25, 10.25, 10.25])),
...         "longitude": ("cluster", np.array([12.25, -3.75, 40.25])),
...     }
... )
>>> placement = create_native_grid_from_dataset(ds, source_spacing=0.5)
>>> placement.adjusted_lats.tolist()
[-0.25, 10.25, 10.25]
>>> placement.lat_spacing, placement.lat_offset
(0.5, -0.25)

create_regular_grid_from_dataset(ds, n_repeat, output_dir, labels_csv=None, min_grid_spacing=0.1, max_grid_spacing=5.0, grid_spacing_steps=100)[source]

Create grid with guaranteed even spacing and minimal deviation from input dataset.

Places each cluster at its centre latitude — center_lat, the latitude of whichever member sits nearest the cluster’s median absolute latitude — on a lattice found by calculate_grid_parameters(). That is not the latitude of the cell whose climate the reduced cell carries: measured on 26 real cluster sets, the two are up to 107° of latitude apart. For the reduced-grid round trip use build_reduced_grid() instead, which places each cell at its own representative coordinates; this function remains the right call when the latitudes genuinely do not lie on a regular lattice and a spacing search is needed.

Parameters:

  • ds (Dataset) – Dataset with cluster centers

  • n_repeat (int) – Number of repeated cells per cluster

  • output_dir (str) – Directory for output files

  • labels_csv (str | None) – Optional CSV file with cluster labels

  • min_grid_spacing (float) – Minimum grid spacing in degrees, and the tolerance for accepting a coarser one. Smaller = finer grid = more RAM. Default 0.1°. On latitudes that already lie on a regular lattice the search returns this value itself rather than coarsening, so it sets the row count outright — see calculate_grid_parameters().

  • max_grid_spacing (float) – Maximum grid spacing to test in degrees. Default: 5.0.

  • grid_spacing_steps (int) – Number of spacing candidates to test. Default: 100.

Returns:

  • Tuple containing

  • - grid_lats (repeated adjusted latitudes (n_clusters * n_repeat))

  • - grid_lons (all longitude values (n_clusters * n_repeat))

  • - adjusted_lats (unique adjusted latitudes per cluster (n_clusters))

  • - global_lons (all longitude values (n_clusters * n_repeat))

  • - lat_spacing (the calculated latitude grid spacing)

  • - lat_offset (the calculated latitude grid offset (x0))

Return type:

tuple[ndarray, ndarray, ndarray, ndarray, float, float]

calculate_grid_parameters(sorted_lats, min_spacing=0.25, beta=0.01, tolerance=None, max_spacing=5.0, spacing_steps=100)[source]

Fast grid detection using candidate-based approach with tolerance-based coarsening.

Algorithm features:

  • O(N) complexity: evaluates spacing candidates from linspace

  • Works on unique latitudes

  • Tests spacings uniformly distributed between min_spacing and max_spacing

  • Accepts grids where all points can shift ≤ tolerance to fit

  • Robust x0 via circular mode on residues with IQR outlier rejection

  • Scoring balances fit quality (median deviation) vs grid parsimony

  • Optional local refinement (±10%) around best candidate

  • Monotonicity validation

⚠ On latitudes that already lie on a regular lattice, ``min_spacing`` is the answer, not a floor. Every candidate spacing then fits to within ~0 deviation, so the parsimony term decides and it always prefers the finest candidate offered. Measured across 26 real cluster sets, this function returned the 0.1° floor in all 26 and never coarsened, which is why the grids built from cluster centres carry a latitude axis about five times longer than their cells need. Callers whose latitudes come off a regular source grid — which cluster centres do — should pass that grid’s own cell size, or place the cells with build_reduced_grid(), which needs no search at all.

Parameters:

  • sorted_lats (ndarray) – Sorted array of latitude values

  • min_spacing (float) – Minimum allowed grid spacing in degrees (default 0.25°). Also serves as tolerance if tolerance is None. See the note above: on regularly-spaced input this value is what you get.

  • beta (float) – Parsimony penalty weight (default 0.01). Higher values favor coarser grids.

  • tolerance (float | None) – Maximum allowed shift for original latitudes (degrees). If provided, only grids with max_dev ≤ tolerance are accepted. If None, uses min_spacing as tolerance.

  • max_spacing (float) – Maximum grid spacing to test in degrees (default 5.0°).

  • spacing_steps (int) – Number of spacing candidates to test between min and max (default 100).

Returns:

Dict with keys – coverage, adaptive_thresh, grid_points, monotonic

Return type:

d, x0, max_dev, mean_dev, median_dev, p90_dev,

verify_written_grid(path, *, source_spacing, n_clusters, n_repeat=1, compact_map_csv=None)[source]

Fail unless the NetCDF on disk carries the placement it was built with.

Checks the three things a silently wrong grid gets wrong: the axes are uniform at the source spacing (so cdf2clm indexes them correctly and declares the right cell size), every cluster occupies its own n_repeat slots and no other cluster’s, and — when the compact map is given — that map points at exactly those slots, which is the only thing the projection back reads.

Give compact_map_csv a path and it must exist: a missing map is an error, not a skipped check.

reconstruct_from_distributed(cluster_file_path, distributed_mapping_file, output_dir, registry, labels_csv=None, *, variable=None, aggregate='mean', output_path=None)[source]

Project output from a distributed grid back onto every cell of the original grid.

In the "distributed" cell choice each cluster was simulated on several of its own member cells, each with a fraction of the patch budget. This combines those cells per cluster — at every time step and for every non-spatial index — and writes the result to every original cell of the cluster.

Parameters:

  • cluster_file_path (str) – A NetCDF on the distributed grid: model output (lat/lon, as LPJmL writes it) or a forcing file this package wrote (latitude/longitude). The file name is not parsed; any name works. A model run may trim empty margins from the grid — chosen cells are located by coordinate, so that is harmless.

  • distributed_mapping_file (str) – The cluster_distributed_mapping_{K}.csv written with the grid.

  • output_dir (str or None) – Directory for the output when output_path is not given (default: beside the input).

  • registry (DataRegistry) – The original grid.

  • labels_csv (str) – The per-cell cell_id,cluster_label table for the whole original grid.

  • variable (str, optional) – Reconstruct only this variable. Default: every variable with both spatial dimensions.

  • aggregate ({"mean", "median"}, optional) – How a cluster’s chosen cells are combined. "mean" (default) is what the vegetation model does across the patches inside one cell, so n cells × p patches then corresponds to one cell × n·p patches. "median" reproduces the reconstruction the method was originally published with. Missing values (NaN, or a fill value of magnitude ≥ 1e30) are ignored.

  • output_path (str, optional) – Exact output path; overrides output_dir.

Returns:

Path to the reconstructed NetCDF. Cells outside the original land mask, and every cell of a cluster none of whose chosen cells has a value, are NaN.

Return type:

str

Raises:

  • FileNotFoundError – If an input is missing.

  • ValueError – On an unknown aggregate, a missing labels_csv, or a model output whose grid does not hold the cells the mapping names.

LPJmL CLM conversion

convert_netcdf_to_clm() turns the reduced-grid NetCDFs into the .clm binaries LPJmL reads. It calls LPJmL’s own cdf2clm / cdf2soil tools, which must be installed. Those tools read each axis’s step from its first and last coordinate only, so every input is first checked with assert_uniform_axes().

convert_netcdf_to_clm(netcdf_files, output_dir, grid_file=None, *, soil_code_file=None, strict=True, uniform_axis_tolerance_deg=0.0001, tools_dir=None)[source]

Convert NetCDF grids to the CLM binaries LPJmL reads, and return what was written.

This is the input half of the reduced-grid round trip: build_reduced_grid() writes one NetCDF per forcing variable, and this turns them into the .clm files a model run consumes. Coordinates are written as floats (both tools are called with -float), which is what keeps them exact — the tools’ integer path truncates rather than rounds, so a coordinate one bit below a lattice point would land a whole step away. Do not drop that flag.

Every input is checked for a uniform axis first (assert_uniform_axes()), because the tools infer each axis’s step from its endpoints alone.

Parameters:

  • netcdf_files (str or list of str) – The files to convert. Unless soil_code_file or grid_file is given, exactly one must be a soil-code file, recognised by "soil_code" in its name; it is converted first because it produces the grid file every climate conversion needs.

  • output_dir (str) – Where the .clm / .bin files land. Created if absent.

  • grid_file (str, optional) – An existing .grid.clm to convert against. When given, no soil-code file is needed and none is converted; a path that does not exist raises.

  • soil_code_file (str, optional) – The soil-code NetCDF that defines the grid, named explicitly instead of found by "soil_code" in a file name – safer when names are your own. It need not be in netcdf_files; if it is, it is converted once, as the grid. Not together with grid_file.

  • strict (bool, optional) – Default True: a failed conversion raises. With False the failure is logged and that file’s entry is None, which is the older behaviour — use it only when a partial result is genuinely useful, never before a model run. A run launched against a silently missing forcing file is the failure this default prevents. An unevenly spaced axis raises ValueError either way.

  • uniform_axis_tolerance_deg (float, optional) – Passed through to assert_uniform_axes().

  • tools_dir (str, optional) – The folder holding cdf2clm and cdf2soil. By default they are looked for in $LPJROOT/bin and then on the PATH.

Returns:

Input path to output path. The soil-code entry maps to the .grid.clm that was written from it. Values are None only when strict=False.

Return type:

dict

Raises:

  • RuntimeError – If no soil-code file is present and no grid_file was given, or — under strict — if any conversion fails.

  • ValueError – If any input’s latitude or longitude axis is not uniformly spaced (whatever strict is), or both grid_file and soil_code_file are given.

  • FileNotFoundError – If an input, grid_file or soil_code_file does not exist.

assert_uniform_axes(netcdf_file, tolerance_deg=0.0001)[source]

Fail unless every spatial axis of netcdf_file is evenly spaced.

cdf2clm and cdf2soil infer each axis’s step from its endpoints and never look at the interior, so an uneven axis is a silently wrong answer rather than an error. This is the check that makes handing them a file safe.

Parameters:

  • netcdf_file (str) – Path to the file about to be converted.

  • tolerance_deg (float, optional) – Largest permitted departure from a constant step, in degrees. Defaults to UNIFORM_AXIS_TOLERANCE_DEG. Loosening this re-opens the hazard — a caller who raises it is asserting that the interior of their axis does not matter, which for a model input it does.

Returns:

The step found for each axis present, keyed by that axis’s variable name. An axis of fewer than three points has no interior to disagree with and is reported as-is.

Return type:

dict

Raises:

ValueError – If any axis’s step varies by more than tolerance_deg. The message names the index where it first happens and both steps, because “the grid is uneven” is not actionable and “row 37 steps 0.75 where every other row steps 0.5” is.
