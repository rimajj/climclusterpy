Feature engineering

Transform loaded climate + soil data into the interpretable feature matrix that clustering consumes: ecological summaries, then standardization / de-correlation / PCA filtering. The mathematics behind each step is in Scientific Methods.

Note

summarize_climate_features() derives optional SPEI / potential-evapotranspiration drought diagnostics via the pyet package, which is not part of the core install: add the [features] extra (or [all]) for it. The rest of the feature pipeline runs on the core install.

Ecological summaries

summarize_climate_features(datasets, registry, variables=None, include_monthly_climatology=True, variable_aggregations=None)[source]

Compute ecological summary statistics for climate variables.

For each grid cell, computes interpretable summaries that capture annual means, seasonal patterns, and extremes.

Parameters:

  • datasets (dict[str, Dataset]) – Dict mapping variable names to xarray Datasets Expected keys: ‘tas’, ‘pr’, ‘rsds’, ‘rlds’, ‘hurs’

  • registry (DataRegistry) – DataRegistry containing valid cell mask and coordinates

  • variables (list[str] | None) – List of variables to summarize (default: all climate vars + SPEI)

  • include_monthly_climatology (bool) – If True (default), include 12 monthly climatology features for temperature (tas_month_01..tas_month_12) and precipitation (pr_month_01..pr_month_12). These are needed for Köppen-Geiger classification.

  • variable_aggregations (dict[str, str] | None) – For a variable the package doesn’t specially know (anything outside tas/pr/rsds/rlds/hurs/spei), whether its monthly climatology should be a mean or a sum (default: mean). Ignored for the known variables, which keep their own fixed recipe (temperature/radiation/humidity: mean; precipitation: sum).

Returns:

  • DataFrame with columns

  • - cell_id, latitude, longitude

  • - tas_mean_annual, tas_month_01..tas_month_12, tas_range, tas_std, tas_seasonality

  • - pr_mean_annual, pr_month_01..pr_month_12, pr_cv_monthly, pr_wetdays_freq, pr_max_monthly

  • - rsds_mean_annual, rsds_seasonal_amplitude, rsds_std

  • - rlds_mean_annual, rlds_seasonal_amplitude, rlds_std

  • - hurs_mean_annual, hurs_std, hurs_dry_min

  • - spei_3_mean, spei_6_mean, spei_12_mean (drought indices at 3/6/12 month scales)

Return type:

DataFrame

summarize_soil_features(datasets, registry, soil_vars=None, encoder_cache_path=None, categorical_vars=frozenset({'soil_code'}))[source]

Extract static (soil, or any other non-climate) features.

Each field in soil_vars is either continuous (kept as a numeric feature) or categorical (one-hot encoded into binary columns named <var_name>_<value>, so that metric-learning algorithms are not misled by the arbitrary ordinal structure of a raw integer code). By default only soil_code is treated as categorical – everything else, including any field outside the original soil_code/soil_depth pair, is continuous unless named in categorical_vars.

Parameters:

  • datasets (dict[str, Dataset]) – Dict mapping variable names to xarray Datasets. Expected keys: 'soil_depth', 'soil_code' (or any other static field name, for a non-LPJmL input).

  • registry (DataRegistry) – DataRegistry containing valid cell mask.

  • soil_vars (list[str] | None) – List of static variables to process (default: ['soil_depth', 'soil_code']).

  • encoder_cache_path (str | None) – Optional path at which to save/reload the fitted OneHotEncoder for each categorical field. Pass a stable path (e.g. inside the feature cache directory) so the encoder is reloaded consistently on subsequent runs. When more than one categorical field is given, each gets its own cache file (the field name is inserted before the file extension).

  • categorical_vars (frozenset[str] | set[str]) – Which of soil_vars are categorical (one-hot encoded) rather than continuous. Default: {"soil_code"}, matching the original LPJmL-specific behavior.

Returns:

  • DataFrame with columns

  • - ``cell_id``, latitude, longitude

  • - one continuous column per continuous field

  • - ``<var_name>_<value>` (binary`, one column per unique category) per categorical field

Return type:

DataFrame

compute_kg_diagnostic_features(monthly_T, monthly_P, latitudes)[source]

Compute KG-diagnostic scalar features from 12-month climatological means.

These features capture the exact quantities used by the Köppen-Geiger classification rule (temperature extremes, precipitation seasonality, aridity) as continuous scalars. They are prefixed with kg_diag_ so that the filtering pipeline can identify and protect them.

Parameters:

  • monthly_T (np.ndarray, shape (n_cells, 12)) – Mean temperature (°C) for each of the 12 calendar months.

  • monthly_P (np.ndarray, shape (n_cells, 12)) – Mean precipitation (mm/month) for each of the 12 calendar months.

  • latitudes (np.ndarray, shape (n_cells,)) – Cell latitudes in decimal degrees (negative = Southern Hemisphere).

Return type:

dict mapping ``kg_diag_*` feature names` to 1-D arrays of length n_cells.

Vegetation-model traits

build_trait_features_df(supervision_data, registry, *, traits=('sla', 'wooddens', 'height', 'vegc'), include_dominant_type=True)[source]

Build a per-cell trait table from model output, in whichever form it arrives.

Parameters:

  • supervision_data (str) – Either a directory of per-trait NetCDF files, or a prepared per-cell CSV. The form is detected from the path (a .csv file vs a directory).

  • registry (DataRegistry) – Registry for the grid being clustered. Defines which cells are valid and in what order, so the returned rows align with the clustering feature matrix.

  • traits (sequence of str, optional) – Continuous traits to read. Defaults to DEFAULT_TRAITS. Common aliases are accepted (biomass matches a vegc file, and so on).

  • include_dominant_type (bool, optional) – Also read the categorical dominant_type when present (default True). It is optional in the input: a run without it still produces usable continuous supervision.

Returns:

Columns cell_id, latitude, longitude, one column per trait, and dominant_type when available. One row per valid grid cell, in registry order.

Return type:

pandas.DataFrame

Raises:

  • FileNotFoundError – If supervision_data does not exist, or a requested trait has no file.

  • ValueError – If a trait column/variable cannot be identified, or the input does not cover every valid cell.

Examples

>>> traits = build_trait_features_df(
...     "/path/to/model_output/trait_grids",
...     registry,
...     traits=["sla", "wooddens", "height", "biomass"],
... )

Remove highly correlated features whose |rho| exceeds threshold.

When two features are correlated above threshold, keeps the one with lower mean absolute correlation to all other features.

Parameters:

  • df (DataFrame) – DataFrame with features

  • feature_cols (list[str]) – List of column names to analyze

  • threshold (float) – Correlation threshold (default 0.9)

  • method (str) – ‘spearman’ or ‘pearson’

  • protected_cols (list[str] | None) – Columns to pass through without analysis. When None (default), any column in feature_cols whose name starts with one of the _AUTO_PROTECTED_PREFIXES (tas_month_*, pr_month_*, kg_diag_*, soil_*) is automatically protected.

Returns:

diagnostic_pca_filter(df, feature_cols, variance_threshold=0.95, contrib_threshold=0.01, protected_cols=None)[source]

Use PCA to identify and remove low-contribution features.

Does NOT project data — only uses PCA for feature selection.

Process:

  1. Compute PCA on analysable features (not protected).

  2. Find the minimum N components explaining at least variance_threshold (e.g. 95%).

  3. For each feature, compute its total absolute contribution across the first N components.

  4. Remove features with contribution below contrib_threshold (e.g. 1%).

Parameters:

  • df (DataFrame) – DataFrame with features

  • feature_cols (list[str]) – List of column names to analyze

  • variance_threshold (float) – Cumulative variance to retain (default 0.95)

  • contrib_threshold (float) – Minimum feature contribution to keep (default 0.01)

  • protected_cols (list[str] | None) – Columns to pass through without analysis. When None (default), any column in feature_cols whose name starts with one of the _AUTO_PROTECTED_PREFIXES (tas_month_*, pr_month_*, kg_diag_*, soil_*) is automatically protected.

Returns:

  • df_filtered (DataFrame with low-contribution features removed.)

  • diagnostics (Dict with the PCA object, component info, contributions, and removed/kept feature lists.)

Return type:

tuple[DataFrame, dict]

apply_block_pca_compression(df, tas_monthly_cols, pr_monthly_cols, cache_dir, variance_threshold=0.99, force_recompute=False)[source]

Replace raw monthly T/P columns with PCA scores (block PCA).

Fits (or loads from cache) one sklearn.decomposition.PCA per block – one for the 12 temperature monthly columns, one for the 12 precipitation monthly columns – retaining enough components to explain variance_threshold (default 99 %) of within-block variance.

The raw monthly columns are dropped from the returned DataFrame and replaced by tas_month_PC1 … tas_month_PCN and pr_month_PC1 … pr_month_PCM.

PCA objects are serialised to {cache_dir}/block_pca_tas.pkl and {cache_dir}/block_pca_pr.pkl.

Parameters:

  • df (DataFrame) – DataFrame containing (at least) the monthly columns.

  • tas_monthly_cols (list[str]) – Ordered list of the 12 temperature monthly column names (e.g. ['tas_month_01', …, 'tas_month_12']).

  • pr_monthly_cols (list[str]) – Same for precipitation.

  • cache_dir (str) – Directory where PCA cache files are stored/read.

  • variance_threshold (float) – Fraction of variance to retain per block (default 0.99).

  • force_recompute (bool) – If True, ignore cached PCA objects and refit.

Returns:

  • df_compressed (DataFrame with raw monthly cols replaced by PC cols.)

  • info (Dict with the fitted PCA objects (pca_tas, pca_pr), the per-block PC counts (n_tas_pcs, n_pr_pcs), and the new PC column-name lists (tas_pc_cols, pr_pc_cols).)

Return type:

tuple[DataFrame, dict]
