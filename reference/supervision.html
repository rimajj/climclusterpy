Supervision labels

The three sources of LMNN class labels, all producing the same cell_id, latitude, longitude, cluster_label table. Reached most easily through compute_supervision(); the generators below, all importable from climclusterpy.supervision, are exposed for finer control.

Perform hierarchical agglomerative clustering on output-derived features.

Uses direct Euclidean linkage on the multivariate feature matrix. The feature matrix does not depend on n_clusters, so the dendrogram is identical for every n_clusters value: it is saved in output_dir and re-cut by later calls. It is reused only for the same feature matrix and linkage method – its file name carries a fingerprint of both – so a call with other traits, cells or values in the same folder builds its own. force_recompute=True rebuilds it regardless.

build_trait_feature_table(features_df, cell_ids, latitudes, longitudes, continuous_cols, categorical_col=None)[source]

Build a features DataFrame for representative-cell selection.

Used with the existing precomputed_features selection method, which merges on (latitude, longitude) and picks the cell whose feature vector is closest (raw Euclidean) to the cluster centroid. Because that selector does NOT standardize, the continuous columns are z-scored here so that the representative is chosen in the same balanced, scale-free feature space used for clustering. Latitude/longitude are included only as plain metadata columns (for the merge), not as clustering features. The one-hot type columns are unit indicators, already comparable in magnitude to the z-scored continuous features.

merge_small_ecoregions(labels, min_cells=10, *, biome=None, realm=None, max_km=1500.0)[source]

Absorb every ecoregion with fewer than min_cells cells into a larger neighbour.

Metric learning draws several same-class neighbours for every cell, which a region with only a few cells on the grid cannot supply. Each such region is merged, in one pass, into the nearest region that has at least min_cells cells, where nearest is the smallest great-circle distance between any cell of the one and any cell of the other (so a region that touches the target wins over one whose middle happens to be closer). Among the regions within max_km, one of the same biome and realm is preferred, then one of the same realm, then any; only when no large region lies within max_km (a remote island) is the nearest one of the same biome, then any, taken at any distance. Only regions that are already large enough are targets, so no chains form and the order the small regions are processed in does not matter.

Parameters:

  • labels (pandas.DataFrame) – One row per grid cell with latitude, longitude (degrees) and cluster_label (the ecoregion id), e.g. from assign_cells_to_ecoregions(). Other columns are carried through unchanged.

  • min_cells (int, optional) – Smallest number of cells a region keeps its own class with (default 10). 0 or 1 merges nothing.

  • biome (dict or pandas.Series, optional) – Each region’s biome and realm ({region id: value}), e.g. the BIOME_NUM and REALM attributes of Ecoregions2017. Without one, the preference for it is left out and distance alone decides among the remaining candidates.

  • realm (dict or pandas.Series, optional) – Each region’s biome and realm ({region id: value}), e.g. the BIOME_NUM and REALM attributes of Ecoregions2017. Without one, the preference for it is left out and distance alone decides among the remaining candidates.

  • max_km (float, optional) – Distance cap of the preferred targets, in km (default 1,500).

Returns:

  • merged (pandas.DataFrame) – labels with cluster_label replaced by the merged class (the id of the region it was absorbed into, or its own).

  • merges (pandas.DataFrame) – One row per absorbed region: source_id, source_cells, target_id, target_cells, rule (which preference chose the target), distance_km and, when given, the biome and realm of both.

Raises:

ValueError – If min_cells is negative, a required column is missing, a region lacks a biome or realm entry, or no region has min_cells cells.

Return type:

tuple[DataFrame, DataFrame]

Daily-input helpers

monthly_climatology_from_daily(temp_da, prec_da)[source]

Reduce daily temperature and precipitation to 12-month climatologies.

Parameters:

  • temp_da (xarray.DataArray) – Daily mean temperature with a time dimension (°C).

  • prec_da (xarray.DataArray) – Daily precipitation with a time dimension (mm/day).

Returns:

  • temp_clim (xarray.DataArray) – Mean temperature per calendar month, dims (month, ...) with month in 1–12 (°C).

  • prec_clim (xarray.DataArray) – Mean precipitation total per calendar month, dims (month, ...) (mm/month).

Return type:

tuple[DataArray, DataArray]

Notes

Precipitation needs two steps, not one. Grouping daily values by calendar month and summing would add up every year’s rain into one figure; resampling to monthly totals first and only then averaging across years gives the per-month total the classification rules are defined on.
