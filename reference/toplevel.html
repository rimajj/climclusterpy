Data, timeseries, I/O & plotting

The lower-level building blocks outside clustering and grid building: data loading and the grid registry, per-cluster timeseries, file input/output, preprocessing and the plotting helpers. Each is importable from its package (climclusterpy.data, climclusterpy.timeseries, …); the grid descriptions are also importable from climclusterpy itself. All of it runs on the core install, except the map plots, which need the [viz] extra.

Data loading & the grid registry

A DataRegistry describes the original grid: its coordinates, which cells exist (those with a soil code) and their cell_id. You rarely build one yourself — create_clusters() makes it and saves it as original_grid.nc in the output folder. When a function asks for one, use DataRegistry.load(path) on that file, or DataRegistry.from_soil_code(path) on the soil-code input the grid was built from; both give the same cell_id for every cell.

class DataRegistry[source]

Bases: object

Central access point for grids and aligned data.

It records which cells of the original grid are land (from the soil-code map) and gives each one a stable cell_id; reconstruction uses it to put values back in place.

Ways to get one:

  • create_clusters() builds it and puts it on its result (clusters.registry), and saves it as original_grid.nc in its output folder;

  • DataRegistry.load() reads such a saved file back;

  • DataRegistry.from_soil_code() builds it from the soil-code NetCDF of the original input – the same file create_clusters was given.

Lower level: DataRegistry().init_original_grid_from_soilcode(soil_code_ds).

classmethod from_soil_code(soil_code, var_name='soil_code')[source]

Build the original-grid description from a soil-code NetCDF (path or Dataset).

Cells where the soil code is missing are not part of the grid. This is exactly what create_clusters() does with its soil_code input, so the same file gives the same cell_id for every cell.

A cell counts as missing when its value is NaN or equals the variable’s _FillValue / missing_value; when neither is declared, the first of -9999, -999, 9999, -32768 and -1000000 that occurs anywhere in the data is treated as the fill value. A soil code of 0 is not a soil type – LPJmL skips such a cell – so it is left out too (with a warning; before 0.3.0 it counted as land). The remaining cells get consecutive cell_id values 0, 1, 2, … in row-major (latitude, then longitude) order. If the variable has a time dimension, only its first time step is used.

Parameters:

  • soil_code (str, os.PathLike or xarray.Dataset) – The soil-code input: a path to the NetCDF file, or an already opened Dataset. A Dataset has its coordinates standardized (see standardize_dataset_coordinates()); a file is opened the way create_clusters() opens it. In both cases the variable is found by exact name, then case-insensitively, then under the aliases soiltexture, soil_tex, soilcode, then as the only data variable in the file, then by a long_name or standard_name attribute containing var_name with underscores read as spaces (“soil code” by default).

  • var_name (str, optional) – Name of the soil-code variable (default "soil_code").

Returns:

A registry holding the original grid, its cell ids and its land mask.

Return type:

DataRegistry

Raises:

  • FileNotFoundError – If soil_code is a path that does not exist.

  • ValueError – If the file cannot be read or no soil-code variable can be identified in it.

Per-cluster timeseries

compute_mean_timeseries(ds, var, labels, output_var_name=None, n_samples=None, min_samples=1, seed=None)[source]

Compute mean timeseries per cluster given a small dataset and label points.

Each labelled point is matched to a grid cell of ds: by id when the labels carry cell_id and ds carries the grid’s original_cell_id map (which attach_original_ids() adds), otherwise to the cell whose latitude and whose longitude are nearest to it (each axis separately, so a point off the grid is snapped to the closest cell rather than rejected). The cluster’s series is the NaN-skipping mean over its matched cells at every time step.

Parameters:

  • ds (xarray.Dataset) – Gridded data with coordinates named exactly latitude and longitude (standardize them first if needed), and optionally an original_cell_id variable on (latitude, longitude) giving each cell’s id (-1 off the grid). The variable var must have dimensions (time, latitude, longitude), (latitude, longitude, time) or (latitude, longitude); a 2-D variable is treated as a single time step. Any other dimension order is read as (time, latitude, longitude) without a check.

  • var (str) – Name of the data variable in ds to average.

  • labels (xarray.Dataset) – One entry per cell along a point dimension, with variables latitude, longitude (degrees) and cluster_label (integer). Points with a label of 0 or below are ignored. An optional cell_id variable is used to match points when ds has original_cell_id; before 0.3.0 it was ignored and matching was always by coordinates.

  • output_var_name (str, optional) – Name of the output variable. Default None: f"{var}_mean".

  • n_samples (int or float, optional) – Average over a random subset of each cluster’s cells instead of all of them: an int is a fixed number of cells per cluster (must be positive), a float in (0, 1) is a fraction of each cluster’s cells, rounded up and at least 1. 1.0 is rejected; use None for all cells. Default None. Cells are drawn without replacement; a cluster with fewer cells than requested uses all of them.

  • min_samples (int, optional) – Lower bound on the number of cells drawn per cluster when n_samples is given (default 1, must be at least 1). A cluster with fewer cells uses all of them and a warning is logged. Has no effect when n_samples is None.

  • seed (int, optional) – Seed for the cell draw when n_samples is given. Default None: a different draw on every call.

Returns:

One variable (output_var_name, or f"{var}_mean") with dimensions ("time", "cluster"). The cluster coordinate lists the positive labels in ascending order; the time coordinate is copied from ds (or is 0, 1, … when ds has none).

Return type:

xarray.Dataset

Raises:

ValueError – If var is not in ds, n_samples/min_samples is invalid, a cell_id is not on the grid of ds, or no point has a positive label.

extract_distributed_cells(clusters, df_labels, preprocessed_climate_data, df_soil_code, df_soil_depth, soil_code_data, soildepth_data, npatch, n_jobs=-1, seed=None, preload=False)[source]

The climate and soil of npatch drawn member cells of every cluster.

The extraction behind representative="distributed". It keeps memory low in four steps:

  1. draw every cluster’s cells up front (metadata only, cheap);

  2. read each grid cell once, however many slots drew it – many of the n_clusters x npatch slots share a cell;

  3. read each climate variable straight from its NetCDF file where that is exact (each stored block holding a drawn cell is decompressed once, and the blocks of all variables are spread over worker processes; on the global daily forcing about 8x faster per variable, with identical values), otherwise stream it in time chunks, never holding the full grid in memory;

  4. join the soil fields with a pandas merge.

As a guide: 18 026 clusters x 50 cells, 5 variables and 43 435 time steps need about 6.3 GB per variable for the unique cells and peak at about 12 GB.

Parameters:

  • clusters (list of int) – The cluster ids.

  • df_labels (pandas.DataFrame) – cell_id, cluster_label, latitude and longitude of every cell.

  • preprocessed_climate_data (dict of str to xarray.Dataset) – The climate variables (may be dask-backed).

  • df_soil_code (pandas.DataFrame) – The soil fields as tables (df_soil_depth may be None).

  • df_soil_depth (pandas.DataFrame) – The soil fields as tables (df_soil_depth may be None).

  • soil_code_data (xarray.Dataset) – The same soil fields as grids (soildepth_data may be None).

  • soildepth_data (xarray.Dataset) – The same soil fields as grids (soildepth_data may be None).

  • npatch (int) – How many cells to draw per cluster.

  • n_jobs (int, optional) – Parallel workers: processes for the direct file read, threads otherwise.

  • seed (int, optional) – Seeds the draw; the same seed and labels give the same cells.

  • preload (bool, optional) – Load a variable that cannot be read directly from its file into memory whole before extracting from it, instead of streaming it (default False).

Returns:

Dimensions cell (n_clusters * npatch) and time. When the expanded array would be too large, the climate variables use unique_cell instead and a _slot_to_unique variable maps each slot to its cell.

align_coords(ds, grid)[source]

Align dataset spatial coordinates to a provided grid.

The dataset’s coordinates are first standardized (renamed to latitude / longitude, rounded, longitudes above 180 shifted into [-180, 180]; see standardize_dataset_coordinates()). Every variable is then sampled at the target coordinates by nearest-neighbour selection (xarray.Dataset.interp() with method="nearest"): values are picked, never averaged or interpolated. A target point outside the dataset’s coordinate range gets NaN.

Parameters:

  • ds (xarray.Dataset) – The data to align. Needs a latitude and a longitude coordinate under one of the accepted names (latitude, lat, Latitude, LAT and the longitude equivalents), in degrees.

  • grid (dict or xarray.Dataset or xarray.DataArray) –

    The target grid, either

    • a mapping with keys "latitudes" and "longitudes", each a 1-D array of coordinate values in degrees, or

    • an xarray object whose latitude and longitude coordinates (under any accepted name) are taken as the target.

    The target values are used as given: they are not rounded or shifted, so give longitudes in [-180, 180] to match the standardized dataset.

Returns:

ds on the target grid, with coordinates named latitude and longitude.

Return type:

xarray.Dataset

Raises:

  • ValueError – If ds or an xarray grid has no recognizable latitude/longitude coordinate.

  • TypeError – If grid is neither a mapping nor an xarray object.

build_features(ds, spec)[source]

Construct simple feature tensors from variables defined in spec.

spec can be a dict {name, temporal_agg?, normalize?} or a list of those. For each entry, produce a variable named name if no aggregation is given, otherwise f"{name}_{temporal_agg}". If normalize=True, standardize each grid cell along its non-spatial axis (see spec below).

Parameters:

  • ds (xarray.Dataset) – Input data with a latitude and a longitude coordinate (any accepted name; they are standardized to latitude / longitude first) and, for any entry with a temporal_agg, a time dimension. A time coordinate that is not datetime-like (e.g. plain integers) is replaced by monthly dates starting 2000-01-01, i.e. the steps are assumed to be consecutive months.

  • spec (dict or list of dict) –

    One feature description, or a list of them. Each is a mapping with keys

    • "name" (str, required) — the data variable in ds to use;

    • "temporal_agg" (str, optional) — "monthly" (mean per calendar month, new dimension month 1–12), "seasonal" (mean per three-month block Jan–Mar, Apr–Jun, Jul–Sep, Oct–Dec, new dimension season 1–4) or "yearly" (mean per calendar year, new dimension year). Means skip NaN. Omit it (or pass None) to copy the variable unchanged;

    • "normalize" (bool, optional, default False) — subtract the mean and divide by the (population) standard deviation of each grid cell along its one dimension that is neither latitude nor longitude: the new month/season/year axis after an aggregation, otherwise e.g. time. A zero standard deviation is replaced by 1. A variable with only the two spatial dimensions is left unchanged. (Before 0.3.0 the last axis was used, which for a (time, latitude, longitude) variable without an aggregation is longitude.)

Returns:

One variable per entry, aggregated variables with dimensions (latitude, longitude, <month|season|year>). Variables without an aggregation keep their original dimension order.

Return type:

xarray.Dataset

Raises:

ValueError – If an entry has no name or names a variable not in ds, if temporal_agg is not one of the three accepted values, if ds has no recognizable latitude/longitude coordinate, or if normalize is asked for a variable with more than one non-spatial dimension.
