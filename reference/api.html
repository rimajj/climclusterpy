Public API — climclusterpy

The whole package in a few calls: shrink a grid (create_clusters()), run your vegetation model on the small one, and get the full grid back (reconstruct_original_grid()). Everything on this page is imported from the package itself:

from climclusterpy import create_clusters, reconstruct_original_grid

Heavy or optional dependencies (torch for metric learning, geopandas for ecoregions, pyet for SPEI) are imported inside the functions that use them, so import climclusterpy works on the core install.

The two headline functions

Between them these cover the full workflow: reduce the grid, run your model, rebuild the original resolution.

create_clusters(climate_input, n_clusters=None, *, fraction=None, locally_weighted=False, learned_metric=None, supervision=None, supervision_data=None, include_dominant_type=True, supervision_granularity=None, ecoregions_shapefile=None, ecoregion_id_column='ECO_ID', ecoregion_min_cells=10, lmnn_mode='lowrank', lmnn_k=None, rank=None, seed=0, lmnn_kwargs=None, linkage_method='complete', supervision_linkage='complete', representative='auto', placement='native', output_dir='./climcluster_output', n_repeat=1, npatch=250, cells_per_cluster=None, climate_variables=None, correlation_threshold=0.9, pca_variance_threshold=0.95, pca_contrib_threshold=0.01, min_grid_spacing=None, n_jobs=-1, preload_climate=True, overwrite=True, write_fields=None)[source]

Turn a climate grid into a model-ready cluster grid, in one call.

Runs the whole reduction: load the input, summarize it into ecological features, optionally learn a distance metric from supervision, cluster the cells, pick a representative cell per cluster, and write the reduced-grid NetCDFs plus the mapping CSVs that reconstruct_original_grid() needs to undo it.

Parameters:

  • climate_input (DataPaths, GenericInputs, dict or str) – The climate and soil input: a DataPaths, a mapping of its field names to paths, or a directory holding one NetCDF per input named after the field (temperature.nc, precipitation.nc, soil_code.nc, …). For a model other than LPJmL, a GenericInputs: any named climate and static fields and any land mask. Its static fields are used for clustering and written to the reduced grid under their own names.

  • n_clusters (int, optional) – Number of clusters (the paper’s K) — i.e. how many cells the reduced grid will have. Give this or fraction, not both.

  • fraction (float, optional) – The number of clusters as a share of the input’s valid (land) cells, in (0, 1]: fraction=0.01 on the 67 420-cell half-degree land grid is n_clusters=674 (rounded to the nearest whole number, at least 1). It counts clusters, not the cells the model then runs: with representative="distributed" each cluster is run on cells_per_cluster cells. The number used is logged and kept in diagnostics.

  • locally_weighted (bool, optional) – False (default) clusters under plain Euclidean distance: no supervision, no training, no optional dependencies. True learns a locally-weighted LMNN metric first, so ecologically meaningful directions in feature space count for more. Needs the [lmnn] extra. The trained metric is saved to <output_dir>/learned_metric (see CreateClustersResult.learned_metric_dir).

  • learned_metric (LearnedMetric or str, optional) –

    Cluster under a metric trained earlier instead of training one: a LearnedMetric from load_metric(), or a path it accepts (the learned_metric folder of an earlier run, or a model.pth). Nothing is trained, so supervision, supervision_data, lmnn_k, rank and lmnn_kwargs are refused, and lmnn_mode and the training use of seed are ignored. The input’s features must be exactly the ones the metric was trained on – same number and, when the metric records them, the same names in the same order – or it raises; a metric that records no names (a bare model.pth) is checked on the number only, with a warning.

    What is guaranteed. Same features, same metric, same linkage_method and n_clusters: the labels are the ones the metric was deployed with, provided the distances are computed on the same kind of device (a GPU and a CPU differ in the last bits of float32 arithmetic, which can flip a near-tied merge). Checked on the published global metric, see the changelog. What is not. The package standardises each feature against the input it is given, so the features of another climate or another region are on that input’s own scale, not the training one’s; applying a metric there is legitimate but no longer a reproduction. To transfer a metric to a new climate on the training scale, build the feature matrix yourself and use cluster_matrix() with learned_metric=.

  • supervision (str or sequence of str, optional) –

    locally_weighted=True only: what the learned distance is taught to reproduce.

    • "koppen_geiger" — Köppen–Geiger climate classes computed from the climate input itself; no extra data.

    • "ecoregions" — the polygons of ecoregions_shapefile (needs the [ecoregions] extra); no model output.

    • a model-output trait such as "biomass", or several, such as ("sla", "wooddens", "height", "biomass") — clustered from supervision_data, which is then required. Common aliases are accepted, so "biomass" matches a vegc file.

    • labels you already have — a SupervisionResult (e.g. from compute_supervision()), a table or .csv file with cell_id and cluster_label columns (matched to the grid by cell_id), or an array of labels in the order of the grid’s land cells. Nothing is recomputed, so cached labels (such as a Köppen–Geiger map that must not be re-derived) are used as they are.

    Default None: those four traits when supervision_data is given, Köppen–Geiger otherwise.

  • supervision_data (str, optional) – Trait supervision only, and required there: the vegetation-model output to learn from, as either a directory of per-trait NetCDFs or a prepared per-cell CSV (auto-detected).

  • include_dominant_type (bool, optional) – Trait supervision: also use the categorical dominant_type trait when the input has it (default True).

  • supervision_granularity (int, optional) – How many supervision classes to form from the traits. Defaults to roughly one class per 316 cells, clamped to [30, 674] — 213 classes for the global 67,420-cell grid.

  • ecoregions_shapefile (str, optional) – supervision="ecoregions" only, and required there: the polygon shapefile. A cell gets the polygon its centre falls in, or the nearest one.

  • ecoregion_id_column (str, optional) – supervision="ecoregions" only: the attribute holding the region id (default "ECO_ID").

  • ecoregion_min_cells (int, optional) – supervision="ecoregions" only: an ecoregion with fewer cells than this on the grid is merged into the nearest larger one, preferring the same biome and realm within 1,500 km (see climclusterpy.supervision.merge_small_ecoregions()), because metric learning needs several same-class neighbours for every cell. Default 10, which turns the 815 Ecoregions2017 regions on the global half-degree land grid into 623 classes. 0 keeps one class per ecoregion.

  • lmnn_mode (str, optional) –

    Which distance is learned (see climclusterpy.clustering.lmnn):

    • "lowrank" (default) — a low-rank Mahalanobis metric for every cell, which also captures how features interact. The configuration of the published results.

    • "global" — one linear metric for the whole grid.

    • "local" and "enhanced" — a diagonal metric for every cell (one weight per feature, no interactions); "enhanced" adds class prototypes and oversampling for supervision classes of very uneven size.

  • lmnn_k (int or None, optional) – Number of target neighbours per cell during metric learning (default 5). Not accepted by lmnn_mode="lowrank", which derives k per anchor.

  • rank (int or None, optional) – lmnn_mode="lowrank" and "global": the rank of the learned metric, i.e. how many directions in feature space it can stretch. Default None: with "lowrank" 16, or the number of features if that is smaller – the setting of the published global application (16 on 25 features); with "global" the full rank, one direction per feature. Raises with "local" and "enhanced", whose metric is diagonal and has no rank.

  • seed (int or None, optional) – Seed for every random number generator metric learning draws from, and for the cell draw of representative="random" / "distributed". Default 0, so two identical calls give identical clusters and cells, at any n_jobs. None draws afresh on every call. It changes nothing where nothing is random: Euclidean clustering with a computed representative, or a learned_metric.

  • lmnn_kwargs (dict, optional) – Extra keyword arguments forwarded to the LMNN trainer. An unknown key raises TypeError instead of being silently dropped.

  • linkage_method (str, optional) – SciPy linkage method for the agglomerative cut (default "complete").

  • supervision_linkage (str, optional) – Linkage method for the supervision dendrogram – the one that turns continuous traits into supervision_granularity classes. Default "complete", as in the published results. "average" (the default before 0.4.0) chains badly on these traits: one giant class persists even at very high granularity, so it gives weaker supervision. Distinct from linkage_method, which cuts the cells under the learned metric.

  • representative (str, optional) –

    Which real cell(s) stand for each cluster:

    • "medoid" — the member with the smallest total distance to the others, in the learned metric;

    • "centroid" — the member nearest the cluster mean in feature space;

    • "auto" (default) — medoid when a learned metric is available, centroid otherwise;

    • "random" — one member drawn at random; no representative is computed. The drawn cell keeps its own soil and is placed at its own latitude;

    • "distributed" — cells_per_cluster members drawn at random, each written at its own position on the source grid and each run with npatch // cells_per_cluster patches. No representative is computed, and the cluster’s result is the mean (or median) of its cells, taken by reconstruct_original_grid(). A cluster smaller than cells_per_cluster has every member repeated (plus a random remainder).

    Every choice costs the model the same npatch patches per cluster, so their results are comparable. See the “Choosing the cells” how-to.

  • placement ({"native", "cluster_center"}, optional) –

    Where a "medoid" or "centroid" cell is written on the reduced grid ("random" and "distributed" always write each drawn cell at its own position):

    • "native" (default) — at the latitude of the cell whose climate it carries, on the source grid’s own latitude spacing, so the model computes day length for the latitude that climate came from.

    • "cluster_center" — at the latitude of the member nearest the cluster’s median absolute latitude, on a lattice searched with min_grid_spacing. This was the only layout before 0.3.0; keep it to reproduce an earlier grid. That member is usually not the one whose climate is written there: across 26 real cluster sets, 17–100 % of clusters ended up away from their own climate’s latitude, by up to 107°, some in the other hemisphere — up to 9.5 hours of day length.

  • output_dir (str, optional) – Where the NetCDFs, label table, and mapping CSVs are written.

  • n_repeat (int, optional) – Copies of the one chosen cell written per cluster (default 1). Not used with representative="distributed".

  • npatch (int, optional) – The patch budget per cluster (default 250). With one cell per cluster that cell runs all of it; with "distributed" it is split evenly, and CreateClustersResult.patches_per_cell says what to set as the vegetation model’s patch count. Recorded in every NetCDF’s attributes.

  • cells_per_cluster (int, optional) – representative="distributed" only, and required there: how many member cells per cluster to simulate. Must divide npatch.

  • climate_variables (sequence of str, optional) – Climate variables to summarize. Defaults to ("tas", "pr", "rsds", "rlds", "hurs"). Add "spei" for drought diagnostics — that needs the [features] extra (pyet).

  • correlation_threshold (float, optional) – Feature-filtering thresholds: drop features correlated above correlation_threshold, keep components explaining pca_variance_threshold of variance, and drop features contributing less than pca_contrib_threshold.

  • pca_variance_threshold (float, optional) – Feature-filtering thresholds: drop features correlated above correlation_threshold, keep components explaining pca_variance_threshold of variance, and drop features contributing less than pca_contrib_threshold.

  • pca_contrib_threshold (float, optional) – Feature-filtering thresholds: drop features correlated above correlation_threshold, keep components explaining pca_variance_threshold of variance, and drop features contributing less than pca_contrib_threshold.

  • min_grid_spacing (float, optional) – placement="cluster_center" only: minimum latitude spacing of the reduced grid, in degrees (default 0.1). Larger values give a coarser, much less memory-hungry output grid. Ignored, with a warning, under placement="native", whose spacing is the source grid’s.

  • n_jobs (int, optional) – Parallel workers for timeseries extraction (-1 = all cores).

  • preload_climate (bool, optional) – Load the climate arrays into memory before the threaded extraction (default True). Faster and thread-safe, but holds the input in RAM — set False for a very large grid on a small machine.

  • overwrite (bool, optional) – Recompute and overwrite existing outputs in output_dir (default True). False reuses NetCDFs that are already there.

  • write_fields (sequence of str, optional) – Write only these input fields for the reduced grid (default None: all of them), named as the input names them ("soil_code", "temperature", …). The label table and the mapping CSVs are always written, so the result still reconstructs. This is for a model that reads its inputs from the original files through the mapping (see subset_inputs()) and needs only the grid: write_fields=("soil_code",) with representative="distributed" reads and writes no climate at all, which on a daily global forcing is the difference between an hour and seconds. With the other cell choices the climate is still read to pick and check the cells; only the writing is skipped. An unknown name raises ValueError.

Returns:

The written NetCDFs, the per-cell labels, the mapping CSVs, and the registry — everything reconstruct_original_grid() needs.

Return type:

CreateClustersResult

Raises:

  • ValueError – On an unknown representative/lmnn_mode, an input that cannot be resolved, or supervision that does not cover the grid.

  • ImportError – For locally_weighted=True without the [lmnn] extra.

Notes

Cells are tracked by cell_id throughout, and the trait/supervision tables are checked cell-by-cell against the grid rather than by row count — a same-length but differently-ordered input is an error, not a silent mis-assignment.

Examples

>>> clusters = create_clusters("/data/climate", n_clusters=2000)
>>> sorted(clusters.netcdf_files)

reconstruct_original_grid(model_output, clusters=None, *, registry=None, id_mapping_csv=None, compact_map_csv=None, output_dir=None, kind=None, distributed_mapping_csv=None, labels_csv=None, aggregate='mean')[source]

Project model output from the reduced grid back onto the full original grid.

Every original cell inherits the value of the cluster it belongs to, so a simulation run on n_clusters cells becomes a full-resolution field. Cells are placed by ID through the mapping CSVs, never by coordinate matching.

Parameters:

  • model_output (str or sequence of str) – The NetCDF(s) the vegetation model produced on the reduced grid — a single file, several files, or a directory of them.

  • clusters (CreateClustersResult or str, optional) – The result of create_clusters(), or the output_dir it wrote to (which is read with load_clusters() – the way back in a later session). Supplying it is the one-liner path: the registry and both mapping CSVs come from it.

  • registry (DataRegistry, optional) – Original-grid description. Required when clusters is not given; get it with DataRegistry.load() (original_grid.nc in the run’s folder) or DataRegistry.from_soil_code() (the soil-code input that was clustered).

  • id_mapping_csv (str, optional) – The cluster_id_mapping_{K}.csv and cluster_compact_map_{K}.csv written when the reduced grid was built. Required when clusters is not given.

  • compact_map_csv (str, optional) – The cluster_id_mapping_{K}.csv and cluster_compact_map_{K}.csv written when the reduced grid was built. Required when clusters is not given.

  • output_dir (str, optional) – Where to write the reconstructed NetCDFs. Defaults to a reconstructed/ directory beside the input.

  • kind ({"output", "distributed"}, optional) – "output" for a grid with one simulated cell per cluster – model output, or the reduced-grid NetCDFs this package wrote – and "distributed" for a representative="distributed" grid. Default: "distributed" when clusters was built that way (or only distributed_mapping_csv is given), otherwise "output".

  • distributed_mapping_csv (str, optional) – Needed for kind="distributed"; taken from clusters when given.

  • labels_csv (str, optional) – Needed for kind="distributed"; taken from clusters when given.

  • aggregate ({"mean", "median"}, optional) – kind="distributed" only: how a cluster’s simulated cells are combined into the value every member receives. "mean" (default) matches what the vegetation model does across the patches inside one cell, so 25 cells × 1 patch compares directly with 1 cell × 25 patches. "median" reproduces the reconstruction the method was originally published with.

Returns:

.files maps each input to its reconstructed output; .path is a shortcut when there is exactly one.

Return type:

ReconstructResult

Raises:

  • ValueError – If neither clusters nor the explicit registry/mapping arguments are given, no NetCDF is found at model_output, or the inputs do not belong together: the two mapping files describe different grids, the model output was produced on another reduced grid (values where this grid has no cluster, or cluster cells missing from it), or the registry is not the grid that was clustered. Nothing is written in that case.

  • FileNotFoundError – If a mapping file or the model output is missing.

Examples

>>> full = reconstruct_original_grid(
...     "vegc_2000_clusters.nc", clusters=clusters
... )
>>> full.path
'./clusters_2000/reconstructed/vegc_2000_clusters_reconstructed.nc'

Before and after the model run

Check the input before a long run, and get a finished run back in a later session — the model run in between usually takes days.

check_inputs(climate_input, *, n_clusters=None, climate_variables=None)[source]

Check a climate + soil input before a long run, and report what is wrong with it.

Runs everything create_clusters() would check, plus a full scan for missing values, without building features or clustering. Use it before submitting a job:

report = check_inputs("/data/climate_input", n_clusters=2000)
print(report)          # grid, time axes, units, and every problem found
report.ok              # False if create_clusters would refuse or go wrong

What it checks:

  • the input resolves – every required file present (see create_clusters());

  • every climate file is on exactly the soil_code grid;

  • the climate files share one time axis (same number of steps, all daily or all monthly);

  • units, judged from the values: temperature in °C or K; precipitation in mm per time step, not a flux in kg m-2 s-1; radiation in W m-2; humidity in %;

  • no missing values on land cells (cells with a valid soil_code) in any input;

  • n_clusters, if given, is a whole number between 1 and the number of land cells;

  • climate_variables, if given, names known variables the input provides.

Parameters:

  • climate_input (DataPaths, GenericInputs, dict or str) – As for create_clusters().

  • n_clusters (int, optional) – The number of clusters you intend to ask for.

  • climate_variables (sequence of str, optional) – As for create_clusters().

Returns:

.ok, .problems and .warnings (lists of plain sentences), and .facts (grid size, resolution, land cells, time steps, units). print() it for a summary. It raises only for an argument of the wrong type; every problem with the data is reported in .problems.

Return type:

InputCheck

Notes

It reads every input in full once, which for a large daily dataset takes a while – but far less than a failed run.

load_clusters(output_dir)[source]

Reload the result of an earlier create_clusters() (or create_regions()) run.

The vegetation-model run between clustering and reconstruction usually takes days, so this is how a later Python session gets back everything reconstruct_original_grid() needs – the mapping files, the per-cell labels and the original-grid description – from the run’s output folder alone:

clusters = load_clusters("./clusters_2000")
full = reconstruct_original_grid("vegc.nc", clusters=clusters)

reconstruct_original_grid(..., clusters="./clusters_2000") does the same in one step.

Parameters:

output_dir (str) – The output_dir the run wrote to. It holds climclusterpy_run.json (written by every run since version 0.3.0) and original_grid.nc. The folder may have been moved: paths are resolved relative to it.

Returns:

As the original call returned it, except that supervision carries only the label table (labels is re-read from its CSV when it still exists) and diagnostics only what could be stored as JSON.

Return type:

CreateClustersResult

Raises:

FileNotFoundError – If the folder, its run record, or a file the record names is missing.

Build a reduced grid from an EXISTING map of regions — no distance learned, no clustering.

This is the cheapest route the package offers, and the one to reach for when there is no historic run of the model to supervise a distance with and no appetite for the clustering step either. An existing categorical map — a Köppen–Geiger climate classification, a published ecoregion map, a management-unit or country layer of your own — is the partition. Every cell keeps the class the map gives it, one representative cell is chosen per class, and the result is the same CreateClustersResult create_clusters() returns, so reconstruct_original_grid() consumes it unchanged.

The number of regions comes from the map; it is counted, not requested. To get, say, 1 % of the cells from a saved table that holds several cuts of one dendrogram (columns cluster_k7 … cluster_k21320), pass fraction=0.01 and the cut nearest that many regions is used and reported, or name the cut with column="cluster_k674".

What it does not do is as important as what it does. No metric is trained, so there is no seed, no supervision signal, no rank and no training time. No dendrogram is built, so there is no \(O(n^2)\) distance matrix and no memory ceiling from one. On the global half-degree land grid that is the difference between an 18 GB array and none at all.

Notes

This is not a cheaper version of supervising a learned distance with the same map. Passing a Köppen–Geiger map to create_clusters() as supervision trains a distance to agree with those zones and then clusters the grid into however many clusters you ask for; the zones themselves are never the partition. Here they are. The two answer different questions and, on the global grid, give materially different accuracy.

The regions of a published map are not balanced. A clustering produces clusters sized by the algorithm; a map produces whatever the cartographers drew. In the WWF/RESOLVE Ecoregions 2017 layer on a half-degree land grid, 31 of the 815 regions present are a single grid cell — which those cells then reconstruct exactly, for no reason connected to the method — while ECO_ID 0, “rock and ice”, is one region of 2 112 cells stretching from Patagonia to northern Greenland. Read the class-size distribution in diagnostics before reading the score.

Polygons in another coordinate system are converted to longitude/latitude; a file without one is assumed to be in longitude/latitude already.

  • ecoregion_id_column (str, optional) – "ecoregions" only: the attribute column holding the region id (default "ECO_ID"). Its values become the class labels, so they must convert to integers.

  • ecoregion_min_cells (int, optional) – "ecoregions" only: an ecoregion with fewer cells than this on the grid is merged into the nearest larger one, preferring the same biome and realm within 1,500 km (see climclusterpy.supervision.merge_small_ecoregions()), because metric learning needs several same-class neighbours for every cell. Default 10; 0 keeps one class per ecoregion. The merges are listed in ecoregion_merges_min<n>.csv beside the labels.

  • cell_ids (array-like, optional) – "output" only, and all three required there: the cell id and coordinates (degrees) of each row of features_df, in the same order. They are copied into the labels table as given; their length and order are not checked against features_df.

  • latitudes (array-like, optional) – "output" only, and all three required there: the cell id and coordinates (degrees) of each row of features_df, in the same order. They are copied into the labels table as given; their length and order are not checked against features_df.

  • longitudes (array-like, optional) – "output" only, and all three required there: the cell id and coordinates (degrees) of each row of features_df, in the same order. They are copied into the labels table as given; their length and order are not checked against features_df.

  • continuous_cols (list of str, optional) – "output" only, and required there: the continuous trait columns of features_df to cluster on. Each is standardized on its own (zero mean, unit variance); a missing value is replaced by its column’s mean first.

  • categorical_col (str, optional) – "output" only: a column of integer category codes (e.g. a dominant vegetation type) added to the continuous traits as unscaled one-hot indicator columns. Default None: no categorical trait.

  • n_clusters (int, optional) – "output" only, and required there: how many classes to cut the trait dendrogram into. It is an upper bound; the dendrogram can yield fewer, and the result’s n_classes is the number actually obtained.

  • linkage_method (str, optional) – "output" only: the SciPy linkage method of the trait dendrogram, built under the Euclidean distance (default "complete", as in the published results; it was "average" before 0.4.0). This is what supervision_linkage sets in create_clusters().

  • cold_threshold (float, optional) – "koppen_geiger" only: the coldest-month mean temperature, in °C, that separates temperate (C) from continental (D) climates (default 0.0; -3.0 is the other common convention). A cell is temperate when its coldest month is warmer than this.

  • output_dir (str, optional) – Directory the underlying generator writes the labels CSV to. If None a temporary directory is created. Earlier results in it are reused only for the same inputs: for "ecoregions" the cell assignment is read back when the grid, the shapefile (path, size and modification time) and ecoregion_id_column all match the call that wrote it; for "output" the trait dendrogram is re-cut when the trait matrix and linkage_method match. Anything else is computed afresh. (Before 0.3.0 both were reused on the file name alone, so a second call with other inputs in the same folder silently got the first call’s labels.)

  • force_recompute (bool, optional) – "ecoregions" and "output": compute afresh even when a matching saved result exists (default False).

Returns:

The per-cell labels table (at least cell_id, latitude, longitude and cluster_label), the kind, the number of classes n_classes and the path of the written labels_csv.

Return type:

SupervisionResult

Raises:

  • ValueError – On an unknown kind or missing required inputs.

  • ImportError – For kind="ecoregions" without the [ecoregions] extra installed.

property slot_sources: DataFrame

one row per slot.

Columns slot, cluster_label, cell_id, source_latitude, source_longitude, grid_latitude, grid_longitude, at_source. source_* is the original cell whose climate and soil the slot carries; grid_* is where the slot sits in the written reduced-grid files; at_source is False where the two differ.

Why it matters. Anything that finds a cell’s data by coordinate – a NetCDF input of the model, a lookup of your own – reads the place at grid_*, which is right only where at_source is True. With representative="distributed" that is every slot except the repeats of a region with fewer cells than draws (each repeat sits at the next free longitude; 2 317 of 16 850 slots at 674 regions x 25 on the global half-degree grid). With "medoid"/"centroid"/"random" the cells are packed into rows, so the latitude is the source’s but the longitude generally is not. subset_inputs() writes each slot’s source values at its grid position, which is the safe way to bring any other input onto the reduced grid.

Raises ValueError for a placement="cluster_center" grid, which records no per-slot position.
