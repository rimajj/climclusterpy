Prepare the input files

create_clusters(), create_regions() and check_inputs() read the climate (and any static fields such as soil) of the original grid from NetCDF files. This page describes how to specify that input, what the files must look like when the code reads them, and what the functions write back. It states where the code does not check something.

Describe the input

You describe the input with four arguments, under the names your model uses:

from climclusterpy import create_clusters

clusters = create_clusters(
    climate={
        "temperature": "/data/tas.nc",
        "precipitation": "/data/pr.nc",
        "short_wave_radiation": "/data/rsds.nc",
    },
    static={
        "soil": ("/data/soil_class.nc", "categorical"),
        "elevation": ("/data/dem.nc", "continuous"),
    },
    grid="/data/gridlist.csv",       # or land_mask="/data/land.nc", or neither
    n_clusters=500,
)
climate

{name: path}: at least one NetCDF with a time dimension, under any names.

static

{name: (path, kind)}: fields without a time axis. kind is "categorical" for a class code, which becomes one 0/1 feature per class (so class 5 is not “more” than class 2), or "continuous" for a measurement. There is no default kind.

land_mask

A NetCDF marking the cells to cluster: a cell is included where the mask is non-zero and not missing. For a file with several variables, (path, variable) names the one to use, for example land_mask=("soil.nc", "soil_class") to cluster every cell with a soil class.

grid

The model’s own cell list, a CSV (or a pandas.DataFrame) with lat and lon columns. The package uses it only without land_mask. The grid’s axes are the distinct latitudes and longitudes in the list, and the package clusters only the listed cells.

With neither land_mask nor grid, the cells are those where every field has data (its first time step, for a climate field).

You can also build the description first as a GenericInputs and pass it in their place. This is useful when several runs share one input:

from climclusterpy import ClimateField, GenericInputs, StaticField

spec = GenericInputs(
    climate={
        "temperature": "/data/tas.nc",
        "precipitation": ClimateField("/data/era5.nc", variable="tp"),
    },
    static={"soil": StaticField("/data/soil.nc", kind="categorical", variable="class")},
    land_mask="/data/land.nc",
)
report = check_inputs(spec, n_clusters=500)
clusters = create_clusters(spec, n_clusters=500)

A file that holds one data variable needs nothing more. When it holds several, or its variable is not named after the field, name the variable with ClimateField(path, variable=...) or StaticField(path, kind, variable=...). With ClimateField(..., aggregation="sum"), a field that is not one of the recognised variables below accumulates over a month (like a second precipitation) instead of being averaged.

You can also give the input in the fixed file layout of LPJmL-FIT, the vegetation model the package was developed with (see The LPJmL-FIT file layout below).

How the package uses the climate fields

A climate field recognised as one of these variables, by its name or the name of its variable (tas or t2m, pr or tp, rsds or SWdown, rlds or LWdown, hurs or rh), gets that variable’s own features and unit checks:

Variable

Units and use

temperature

°C or K. The package recognises Kelvin by its magnitude (a mean above 200 over the cells) and converts it to °C for the features. It does not consult the units attribute.

precipitation

Per time step: mm/month for monthly data, mm/day for daily data. The package does not convert a flux in kg m⁻² s⁻¹, and check_inputs reports it as a problem. Multiply by 86 400 for daily data, or by the seconds in each month for monthly data.

short-wave radiation

Downward short-wave radiation, W m⁻².

long-wave radiation

Downward long-wave radiation, W m⁻².

humidity

Relative humidity, %.

With both temperature and precipitation present, the package also adds the Köppen–Geiger diagnostics (Choose the features lists the columns), and supervision="koppen_geiger" becomes available. Any other climate field is summarised generically: its annual mean (or sum), its spread and, when the series covers whole years, its 12 monthly values and their seasonality, in its own units.

Units matter only where the code compares against a fixed number: the Köppen–Geiger classes (thresholds in °C and mm/month) and the wet-step frequency (the share of time steps with more than 1 mm of precipitation). The package standardizes every other feature before clustering. The reduced-grid NetCDFs that it writes for your model carry your values unchanged, in your units.

Check your input first

Before anything expensive happens, check_inputs() runs the checks below on their own. It returns a report of problems (the run would fail or be wrong) and warnings (the run goes ahead):

from climclusterpy import check_inputs

report = check_inputs(climate={...}, static={...}, n_clusters=2000)
print(report)        # grid size, land cells, time steps, units, sampled ranges
report.ok            # False if create_clusters would refuse the input or go wrong
report.problems      # plain sentences, one per problem
report.warnings

create_clusters() runs the quick checks (grid, time axes, units, judged from the first 24 time steps) on every call. check_inputs additionally reads every time step to look for missing values.

Grid and coordinates

  • Coordinates can be named latitude, lat, Latitude or LAT and longitude, lon, Longitude or LON. The package renames them to latitude and longitude, rounds them to 5 decimals and converts longitudes in 0–360° to −180–180°.

  • The grid that defines the cells is the land mask’s, the cell list’s or, with neither, the first field’s. The package maps a field on a slightly different grid onto it by nearest neighbour and warns how far the largest shift is. It refuses a field that is more than half a grid cell away from some cell. Regrid such a field first, for example with CDO remapnn.

  • The code expects a regular latitude–longitude grid whose 1-D latitude and longitude coordinates are also its dimensions. It does not support curvilinear grids (2-D coordinate arrays on x/y dimensions).

  • The dimension order does not matter (time, lat, lon and lat, lon, time both work).

The time axis

  • Every climate file needs a time dimension, and all of them must share one time axis: the same number of steps, all daily or all monthly. check_inputs and create_clusters refuse a mix.

  • The package accepts monthly and daily data. When the time coordinate decodes to dates (a CF units attribute such as "days since 1901-01-01", any calendar), the step length decides: under 2 days is daily. Without dates the number of steps decides: more than 365 steps is taken as daily for temperature, more than 730 for precipitation, so a long monthly series with a plain integer time axis can be mistaken for daily data. Give the time axis dates to avoid this.

  • Monthly data should start in January and cover whole years. The package forms the 12 monthly means by cutting the series into blocks of 12 steps without reading the dates, so a series that starts in another month gets its months shifted. A series that is not a whole number of years loses its monthly-climatology features and the Köppen–Geiger diagnostics built on them, with a warning.

  • Daily data need dates. The package drops 29 February for the monthly climatology of standard calendars and uses noleap calendars as they are.

Calendars and 29 February

LPJmL and other models with a 365-day year cannot read forcing files that contain 29 February. create_clusters and create_regions write the reduced-grid climate files with the calendar of the input, so daily data on a standard calendar keep their leap days. If a daily input contains 29 February, the run warns once, and check_inputs lists the same warning in report.warnings. To remove the days, pass drop_leap_days=True (command line: --drop-leap-days):

create_clusters(climate=climate, n_clusters=30, drop_leap_days=True)

Every written climate file then has no 29 February and a noleap calendar, with 365 steps per year; the other days keep their values. The option changes only the written files. The features skip 29 February in either case, so the clusters are the same. Monthly input and input already on a 365-day calendar are written unchanged and give no warning. The run record climclusterpy_run.json stores the setting. A 360-day or all-leap calendar cannot be converted to 365 days; the package warns and writes it as it is.

Missing values

The package does not fill missing values.

  • Cells outside the land mask or the cell list (or, for the LPJmL-FIT layout, with a missing soil code) are not part of the grid, whatever their climate.

  • A land cell whose climate is missing at every time step of some input gets NaN features, and create_clusters() stops with an error that names the input, the number of cells and a few of their coordinates.

  • A land cell with some missing time steps does not stop create_clusters. The package computes its summaries from the values that are present. If the package selects that cell for simulation, the gaps go into the reduced-grid file for your model unchanged. check_inputs() reports every such cell. Fill the gaps, or leave those cells out of the land mask or the cell list.

What is written

The package writes every climate field and every static field to the reduced grid under its own name, with each written cell holding its source cell’s value. The pre-0.3.0 layout placement="cluster_center" cannot carry static fields and refuses them, unless you leave them out of the output with write_fields=.

The LPJmL-FIT file layout

LPJmL-FIT reads six fixed files. You can pass a directory that holds them, named exactly as below, as it is (create_clusters("/data/lpjml_input", n_clusters=2000)), as a DataPaths or as a dict that maps these names to paths. The package refuses a directory that lacks a required file and lists what the directory does contain.

File

Required

Content and units

temperature.nc

yes

Air temperature, °C or K (units as in the table above).

precipitation.nc

yes

Precipitation per time step.

short_wave_radiation.nc

yes

Downward short-wave radiation, W m⁻².

long_wave_radiation.nc

yes

Downward long-wave radiation, W m⁻².

soil_code.nc

yes

Soil type as an integer code per cell. It defines the grid (see below).

soil_depth.nc

yes

Soil depth per cell. Used as one continuous feature; its unit does not matter, because every feature is standardized.

humid.nc

no

Relative humidity, %.

Each file can hold one data variable of any name. If it holds several, the package uses the one that matches the input name or a common alias (tas/t2m for temperature, pr/tp for precipitation, rsds/SWdown, rlds/LWdown, hurs/rh, soiltexture for the soil code, soildepth for the depth).

  • Every climate file must be on exactly the grid of soil_code.nc: the same latitude and longitude values in the same order (after rounding to 5 decimals). Otherwise the load stops and says which axis differs.

  • soil_depth.nc can be on a different grid. The package maps it to the soil-code grid by nearest neighbour and warns how far the largest shift is.

The soil code defines the grid. A cell is a land cell, and gets a cell_id, when its soil code is not missing: not NaN and not equal to the file’s _FillValue or missing_value. If the file declares neither, the code looks for the common fill values −9999, −999, 9999, −32768 and −1 000 000 in the data and treats the first one it finds as missing. cell_id numbers the land cells from 0 in row order (latitude, then longitude).

A soil code of 0 is not land. LPJmL has no soil type 0 and skips such a cell, so the package leaves it out of the grid too and warns with the number of such cells (before 0.3.0 it counted as land). If your file uses another value for water or ice, set those cells to missing first, or they become land cells.

The codes are categories. Each distinct code becomes its own 0/1 feature column (soil_code_<value>), so code 5 is not treated as “more” than code 2. If either soil file has a time dimension, the package keeps only its first step.

Output files

A run writes everything into output_dir (default ./climcluster_output). For K clusters, the files are:

File

What it is

<input>_<K>_clusters_clustering_ncells_<n>_<choice>_<mode>.nc

One NetCDF per input field, under its own name, on the reduced grid. This is what the vegetation model runs on. <n> is the number of written cells. Each file also holds a cluster_label variable and records the patch budget in its global attributes (patches_per_cell, npatch_per_cluster, cells_per_cluster, cell_selection). Read the paths from clusters.netcdf_files instead of building the names yourself.

cluster_labels_with_coords_nr_of_clusters_<K>.csv

Every original land cell: cell_id, latitude, longitude, cluster_label.

cluster_id_mapping_<K>.csv

Which reduced-grid cell stands for which original cells: original_cell_id, new_cell_id, cluster_index, cluster_label. Not written for "distributed".

cluster_compact_map_<K>.csv

Where each cluster sits on the reduced grid (its row and column span). Not written for "distributed".

cluster_distributed_mapping_<K>.csv

"distributed" only: each drawn cell’s own coordinates and its position on the written grid.

selected_cells_<K>.csv

Which original cells are simulated for each cluster: cluster_label, cell_id, latitude, longitude, slot.

latitude_adjustments_<K>.csv

The latitude each cluster was meant to be written at and the latitude it was written at. Not written for "distributed".

cell_placement_<K>.csv

"random" only: each drawn cell’s own coordinates and the grid slot it occupies.

original_grid.nc

The original grid: coordinates, cell_id of every cell, and the land mask. DataRegistry.load() reads it.

climclusterpy_run.json

The run record: settings, file list and diagnostics. load_clusters() reads it.

supervision/

LMNN mode only (locally_weighted=True): the supervision labels the distance was learned from.

The list comes from running the one-call example (examples/example_0_one_call_roundtrip.py) with cell_selection set to the default, "random" and "distributed", plus the code for the folder that only LMNN mode writes.
